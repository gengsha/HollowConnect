# HollowConnect 0.2.1

面向《空洞骑士》一代的协作联机模组，Windows 1.5.78.11833 / Unity 2020.2.2f1。

**这是早期版本，仍需逐 Boss 和跨机器实战验收。** 0.1.13 修复 Boss 死亡时持续动作清理异常导致房间登记失效、队友消失及独立战斗的公共故障链，整理入场与重连生命周期，并修复脱离 Boss 层级的子物体在接管时引用失效、残留碰撞的问题。原因和验证边界见 [房间同步修复](docs/ROOM-LIFECYCLE-FIX-0.1.13.md)和[验证记录](docs/VERIFICATION.md)。此前的[救援反馈](docs/RESCUE-FEEDBACK-0.1.12.md)、[死亡与入场规则](docs/DEATH-AND-ENTRY-0.1.11.md)、[格林弹幕修复](docs/GRIMM-MOTION-FIX-0.1.10.md)、[Boss 战斗修复](docs/BOSS-FIXES-0.1.8.md)与[审计发现](docs/AUDIT-REMEDIATION-0.1.7.md)保留。

**本次更新为 0.2.1（2026-10-26）。** 修复结算断线阻塞服务端后续阶段、发送异常被误当作离线、多接收端 FSM 状态互相改写、假骑士战后原生终局未继续，以及 Boss 完成意图在 context 暂缺时丢失的问题。保留入房选档确认菜单及 0.1.39 以前的修复。详见[更新日志](docs/UPDATE-0.2.1.md)。

**当前版本为 `0.2.1`，继续使用测试渠道。** 本轮修复分别通过相关核心与双人／三人实机专项；结果对应各自记录的构建哈希。本次升版打包只做构建和包完整性核验，不追认为最终包完成实机矩阵验收。0.1.38 三人大黄蜂剧情卡门反馈仍未复现，不能认定该现场已修复。

本地世界模式由房主开房时确定，关闭共享时完整存档同步也停用；不同剧情场景各自保留。当前引擎为 `3.0.0-hc13`，附加网络标识为 `0.2.1-l8`，需所有玩家使用相同新构建。验证范围另见 [本地世界审计](docs/LOCAL-WORLD-AUDIT-2026-10-20.md)。

**救援默认不限次数，观战 Beta 默认关闭。** 只有成功骨钉救起才消耗次数，真正坐椅子恢复；下方次数提示仅在消耗后显示 4.5 秒。关闭暗影救援时也能独立开启观战；额度耗尽的观战者仍可免费结算复活。当前规则见 [结算复活整改](docs/SETTLEMENT-RESCUE-2026-10-21.md)。

它包含修改后的 HKMP 3.0 引擎和 HollowConnect 配套模块。所有玩家使用同一完整包；它的协议与原版 HKMP 2.x / 原版 HKMP 3.0 不兼容。HkmpPouch 和丝之歌的模组不是依赖。

**房主和所有队友必须更新到同一个 0.2.1 完整包，并重新开房。** 动态 Boss 血量、Boss 伤害占比榜默认关闭；共享永久进度默认开启，已有配置明确保存的开关值仍保留。FRP 继续使用原来的 UDP 端口设置。

伤害榜由房主在开房前启用，普通 Boss 按单场统计，神居一至五门整门累计。**F1** 隐藏／显示本机面板，隐藏时继续统计；菜单说明集中显示在选项列表下方。

## 安装与开房

1. 解压 `HollowConnect-0.2.1-windows.zip`，关闭游戏。
2. 双击解压目录里的 **一键安装.exe**。它会查找各盘的 Steam 游戏库；找到后点击 **安装 / 更新**。有多个副本时从列表选择，未找到时点击 **选择游戏…** 找到自己的 `hollow_knight.exe`，也可粘贴游戏目录。
3. 启动游戏，在模组菜单的 **HollowConnect** 页面选择房主规则。共享永久进度默认开启，已有配置保存的关闭仍会保留；屏外方位、暗影救援、Boss击败后解除暗影、入场免伤默认开启。房主规则在开房时固定，修改后重新开房生效。
4. 从 HKMP 的 Multiplayer 菜单选择 Host，选择要使用的存档和端口，例如 `26950`。队友选择 Connect，填写主机地址、同一个端口，并选择自己的存档；阅读警告后选择「确认加入」。默认的「取消」会回到选档页，保留连接。
5. 使用现有存档时先保留备份。安装器自动备份游戏原文件、现有 HKMP 文件夹及存档到游戏目录 `.HollowConnectBackups`，并核对兼容程序集和包内 SHA256。

安装器支持 Windows 10 / 11，使用系统自带的 .NET Framework 和 Windows PowerShell；不需要安装 .NET SDK 或自行输入命令。完整解压后运行，保留安装器旁边的文件。游戏装在受保护目录、日志提示写入权限不足时，可右键安装器选择“以管理员身份运行”。安装日志保存在 `%LOCALAPPDATA%\HollowConnect\Installer`。

回退安装：在同一安装器中选择游戏后点击 **卸载并恢复**。这会恢复最初安装前的程序集和 HKMP，保留当前存档；存档备份另存于备份目录 `saves`，不会自动覆盖游玩产生的进度。

从已安装的旧版本更新：关闭游戏，用新包的安装器点击 **安装 / 更新**。每次更新单独备份当前文件，保留玩家皮肤、服务器配置和最初的 `.HollowConnectBackups\latest.txt`，卸载仍可回到最初安装前的状态。安装中途失败会逐项恢复本次操作前的文件；文件仍被其他程序占用而无法恢复时，日志会明确列出失败文件和备份位置，备份中另存 `install-failure.txt`。请关闭占用程序后再处理，不能把失败提示视为安装完成。

需要命令行时，可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1` 自动定位，或追加 `-GamePath "自己的游戏目录"` 指定位置；卸载使用 `Uninstall.ps1`。这些脚本没有固定盘符或安装路径。

## 联机与内网穿透

只使用 **一个 UDP 端口**。局域网、ZeroTier / Tailscale 等虚拟局域网，可直接填写房主的相应 IP。公网端口映射或内网穿透必须支持 UDP；只转发 TCP 的 HTTP 隧道不能承载这个协议。

FRP 示例见 [frpc.example.toml](docs/frpc.example.toml)。房主运行 `frpc -c frpc.example.toml`，把公网 UDP 端口转发到本机开房 UDP 端口。队友连接 `frps` 服务器的公网地址和 `remotePort`。防火墙需允许游戏及该 UDP 端口。无需额外架设 HollowConnect 服务。

## 功能与操作

| 功能 | 行为 |
|---|---|
| 紧急回椅 | **Ctrl+Alt+F12**：已载入存档内无须正常控制或联机即可触发，断开本机联机后返回德特茅斯长椅并自动保存；不执行死亡扣费、不清暗影和永久进度。主菜单及进程完全冻结时不能使用。 |
| 诊断工具 | **F9** 打开只读状态面板，支持导出诊断；单人和断线状态也可用。 |
| 怪物同步 | 每个房间只有一个模拟权威；同步位置、动画、支持的 FSM 动作、无敌与碰撞、血量和阶段字段。血量变化即发，未变化每秒保活。进入已有战斗的房间获取快照；权威离开后先应用快照再接手。普通 HP 不能复活死敌，阶段重置须有更新的明确复位，池化重生使用新 ID。 |
| 死亡排行榜 | 按住 **F5** 查看本存档按名字累计的死亡次数；倒地即计数，救援/正式返回不重复计数，重开房间保留，离线队友仍在榜。随游戏正常保存到独立的 `user槽位.modded.json`；卸载模组不改变原版存档读取。同名合并，改名另列；旧版未记录的死亡无法补算。 |
| 可选共享进度 | 永久能力按 OR 合并，法术按最大等级合并；护符槽、面具碎片、容器碎片、苍白矿石及简单钥匙按固定来源每个存档共享一次，已消费的矿石和钥匙不会因重连补回。钥匙四处门锁各自开启、各自消费，后加入者按来源补领钥匙。每次入队全员核对，恢复可证明完整领取的满档来源，并补齐缺少的非消耗资源。远端碎片直接结算并显示原版左下角提示，本地首次领取保留原版动画，重复领取正常收尾且不增加奖励。骨钉升级各自独立。详见共享进度清单。 |
| 地图定位 | 独立于任性指南针和地图探索共享，每秒更新 10 次，名字与颜色标识队友。定位失效、切房间和超过 2 秒未更新时隐藏旧图标，不拿旧坐标冒充实时坐标。游戏本身没有地图坐标的房间以名字和房间名列出。 |
| 屏外提示 | 可在模组菜单关闭。同房间用屏幕边缘箭头和名字指示方位；跨房间直接列出房间名，不把两个不同房间的世界坐标相减来误报方向。 |
| 隐藏传送 | **F7** 循环选择指定队友，**F8** 传送。支持跨房间；服务端校验队友在线、存活、位置新鲜且不在全队重试中。冷却 3 秒；落点避开地形碰撞。按键和房主的 `AllowTeleport` 只在 JSON 配置中提供。 |
| 暗影救援 | 普通流程优先在死亡侧寻找可站立、可挥钉救援的支撑；致命尖刺、酸水或坠落优先回溯本次访问中真实走过的安全位置。无地面阶段可在存活队友能够接近、复活后有安全恢复路线时使用空中救援点，并恢复原生重力与空中动作。倒地后持续重验，平台失效或旧点危险覆盖时经服务器确认重新落位；无安全点或明确封门隔离时按原版个人死亡返回，神居继续原落位算法。存活队友实际挥钉击中暗影后，死亡玩家**恢复 1 格血、0 格蓝血**并获得原版基础受伤无敌；服务器确认的救人者获得 **33 点灵魂**，双方可见原生暗影破碎动画、粒子和音效。仅靠近或挥空不会救起，重复命中只生效一次；暗影轻微悬浮、不追人、不攻击。 |
| 梦钉队友 | 梦之钉实际命中同房间的存活队友，施放者获得灵魂；每次挥击最多结算一次，奖励交替为 16、17 点，两次共 33 点，够普通聚焦回复一格血。梦之支配者不增加此奖励，满魂时沿用原版上限。 |
| 倒地反馈 | 临时倒地不播放死亡动画。所有在线玩家收到一次原版受击音效；同房间在死亡点显示小型原版受击粒子。粒子限量且按真实时间清理，暂停或受击停顿时不持续积累。 |
| 入场免伤 | 房主可关闭。到达新房间后，等待场景、同步快照、镜头和操作就绪，再保留 1.5 秒反应时间。期间敌人攻击不扣血，地形危险仍按原版把玩家送回危险重生点而不扣血。同次入场结束后，战斗中失去操作不能再次触发免伤。 |
| 救援次数 | 房主菜单选择每人不限／1／2／3／5／10 次，默认不限。只有成功骨钉救起才消耗一次，下方剩余次数仅消耗后显示 4.5 秒；真正坐椅子恢复，死亡返回、切房、重试不恢复。 |
| 观战 Beta | 房主菜单“救援耗尽后观战（Beta，房主）”默认关闭，可独立于暗影救援开启。Boss 战中救援不可用时隐藏死亡本体并跟随同房存活队友；**F7** 选队友，**F6** 提前返回。实际受伤的短暂状态继续跟随；房内无人能战斗时按个人原版死亡返回。 |
| 主动放弃 | 暗影形态按 **F6**：观战开启则直接观战，关闭则按原版死亡返回个人长椅或隐性复活点；已经观战时再次按 **F6** 可提前返回。正式死亡保留当地原版掉钱与暗影规则，不推进全队重试编号。 |
| Boss 结算复活 | “Boss击败后解除暗影”开启时，本场暗影可在同场原始存活参战队友处一血复活；观战者也可复活。结算不扣救援次数，额度耗尽也可参与。战利品、封门、神居下一面和结局继续走各人的原生流程；没有同场存活参战者时不凭空复活。 |
| Boss 本场失败 | 房内最后一名可战斗玩家倒地即结束本场；暗影与观战者不算可战斗玩家，房外赶路队友不维持本场。仅送回本场倒地者，不挪动赶路队友或重置其房间。 |
| 全队失败 | 最后一个玩家倒地后统一增加重试编号，清理旧怪物缓存。每个玩家执行一次原版死亡流程，各自返回个人长椅或原版隐性复活点；所有仍在线玩家完成加载后恢复控制。普通流程掉钱并保留原版暗影规则，梦境、神居和白宫等例外交给原版处理。 |

个人复活信息在倒地时冻结，不会复制主机或队友的长椅。某人仍在加载时，全队等待；该玩家断开后从等待名单中移除。已接受的原版死亡流程在断线后仍继续。迟加入全队重试的玩家没有在上一轮死亡，返回自己的检查点而不收取死亡代价。钢魂存档保留原版死亡，不应用救援拦截。

共享项包括移动能力、梦之钉和梦之门、灯笼与电车通行证、骨钉技、法术等级、护符获得标记、地图和羽毛笔购买状态、护符槽、面具碎片、容器碎片、苍白矿石及列出的永久 Boss / 门事件。精确名单见 [共享进度清单](docs/SHARED-PROGRESS.md)。**吉欧、精华、骨钉升级、消耗钥匙和装备状态各自独立，不共享全部存档字段。** 探索、地图绘制、长椅和死亡暗影记录独立。不会自动回退旧版已误升的骨钉；来源消息到达前双方同时购买仍可能各自付费。

掉线超时、被踢、封禁或服务器关闭导致返回主菜单时，先清理联机临时状态，等待正在进行的原生切场完成，再保存当前本地槽位；收到保存成功回调后才卸载场景。保存失败会取消退出并提示在暂停菜单重试，保留当前游戏中的进度。仍在标题或选档菜单、尚未进入存档时不会保存临时数据。

本版怪物注册表包含 258 个条目、239 种实体类型，其中也包括门、机关、弹幕等对象。见 [实体支持清单](docs/SUPPORTED-ENTITIES.md)。没有对全部实体逐一实战验证；第三方新增敌人和不在注册表内的对象没有通用正确性保证。

配置文件由 Modding API 保存于 `%USERPROFILE%\AppData\LocalLow\Team Cherry\Hollow Knight\CoopMod.GlobalSettings.json`。可设置 `ShareCharms`（默认 `true`，也可在模组菜单设置）、`DeathLeaderboardKey`（默认 F5）、`GiveUpKey`（默认 F6）、`SelectTeammateKey`、`TeleportKey`、`AllowTeleport`；游戏关闭后编辑，保留合法 JSON。房主在开房前设置 `ShareProgress: true` 后，`ShareCharms: false` 可单独关闭护符获得状态同步；护符槽继续按来源共享，装备各自独立，已获得护符不会撤销。旧版本的 `RescueKey` 与 `RescueHoldSeconds` 已弃用，现有 JSON 中残留这两项也不会启用按键救援。

在游戏的 **选项 → 模组 → HollowConnect** 中设置：**队友透明度（本机）** 默认关闭（不透明），影响本机看到的队友身体与特效；**队友名字配色（本机）** 默认开启，名字沿用地图/方位颜色，自己保持白色，关闭后头顶名字为白色。这两项各自设置、立即生效，不影响其他玩家。**动态 Boss 血量（房主）** 默认关闭，房主开房前开启，改动后重新开房；访客设置不影响房间。这三个菜单项已随 0.1.27 提供。

配置文件仍支持 `OtherPlayerOpacity`（0～1，默认 1）、`ColoredPlayerNames`（默认 `true`）、`BossHealthScaling`（默认 `false`）。已有配置原值会保留；菜单正确显示自定义透明度。`BossExtraHealthPerPlayer: 0.6`、`BossExtraHealthDecay: 0.6` 对应同房 2 人 160%、3 人 196%、4 人 217.6% 等效血量；按后续有效伤害折算，保留原生阶段血量与过场阈值。设置说明与历史战斗验收见 [队友显示与 Boss 难度](docs/PLAYER-DISPLAY-BOSS-BALANCE-2026-10-19.md)，菜单补全见 [菜单设置修订](docs/DISPLAY-MENU-2026-10-20.md)。

## 源码与验证

源码包含完整 HKMP 修改源、核心协作模型、模块、回归程序和打包脚本。日常运行 `powershell -ExecutionPolicy Bypass -File .\scripts\Build.ps1` 只做增量编译；首次缺引用时可追加 `-GamePath "游戏目录"`，后续仅显式 `-RefreshReferences` 才重新准备游戏引用和官方 Modding API v77。测试与打包分开执行，命令见 [日常开发入口](docs/DEVELOPMENT.md)，需要 .NET SDK 9 或更新版本。完整发行仍要求对应运行验收；没有对应验收不会自动授予发布通过。没有把用户的原版游戏程序集放入源码包。

首版自动化测试包含共享能力幂等、乱序进度合并、救援距离 / 场景 / 时效校验、双方倒地顺序、迟加入、断线解除重试屏障、地图投影、消息集合序列化、血量乱序与死亡快照，以及五客户端并发真实加密握手。完整实机验收步骤在 [验证记录](docs/VERIFICATION.md)，架构说明在 [设计说明](docs/DESIGN.md)。
