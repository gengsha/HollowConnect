# Boss 同步与原生收尾

战斗实体一致不代表每个客户端的原生战斗控制器都已启动或完成。Boss 的 AI／伤害由唯一场景权威执行，本地门、镜头、奖励和剧情仍需要各自合法续接。

## 入口与本地控制器

只有匹配房间、实体类型和已核对的原生 FSM 结构才允许补齐入口事件。保留原生检测、Music／Start、分波计数和本地关门；不把休眠快照或普通零血当成启动／结束信号。主场景与附加 Boss 场景的对象所有权必须明确。

## 阶段、死亡与重入

血量、终结死亡和显式生命重置使用版本化快照。多阶段 Boss 的 `hasSpecialDeath` 零血可以是阶段交接，不能直接写最终击败。真正终结后保留死亡记录和原生持久化标识，防止后来者或重新进房看到活 Boss；临时召唤物退役与永久击败分开处理。

权威移交需带上阶段字段、FSM、本地引用和动态生成关系，先提交快照，再恢复模拟。战斗收尾应沿原生事件与回调推进本地门禁、奖励、神居行程和个人结局；不能靠批量开门、强切下一房或直接标记完成掩盖中间状态。

## 观战与验证

主动观战者退出伤害、索敌和动态增血人数，但仍接收解除本地等待所需的结算通知；它不作为等待结算回执的战斗成员。死亡观战使用独立生命状态和救援／返回规则，详见 [观战说明](../OBSERVATION.md)。

抽样至少区分双方先入、权威与远端、迟入、共享开／关、分阶段与附加场景、战后重入，以及实际移动穿过出口。对门状态或血量的单一断言不等同于玩家能正常离场。已有抽样结论不能扩大为所有 Boss 认证。

实现入口为 `src/HKMP/Game/Client/Entity/`、`src/HollowConnect/BossVictoryRescue.cs`、`BossTravel.cs` 与 `src/HollowConnect.Core/BossVictoryRecovery.cs`。测试入口见 [测试目录](../TEST-INVENTORY-2026-10-18.md)。旧版分析与分组结果见 [原始报告目录](https://github.com/gengsha/HollowConnect/tree/c1a6d16fb5cf14b1f8470bf8c8b18b8f74349a2b/docs)，当前交付边界见 [验证范围](../VERIFICATION.md)。
