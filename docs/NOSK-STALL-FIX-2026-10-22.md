# 诺斯克台阶卡住修复

反馈：剧情诺斯克冲刺时卡在中央平台侧面。

## 诊断和修复

隔离双端在原生 `Deepnest_32` 复现：`Mimic Spider` 停在 `(87.3, 5.9)`，主控制器为 `Charge R`，辅助 `Climb` 控制器为 `Climbing`，刚体速度归零并持续不动。第一次观察中的稳定卡住样本约 8 秒。

`EntityInitializer.CheckPreProcessFsm` 为重新绑定动作引用调用 `Fsm.Preprocess(owner)`。原生方法先执行 `ResetEventHandlerFlags`，清除 `HandleFixedUpdate` / `HandleLateUpdate`。已经初始化的动作不会再次执行 `Awake`，因而无法重新声明更新要求。诺斯克爬升动作 `SetVelocity2d(y=20, everyFrame=true)` 只在进入状态时设置一次速度；重力很快抵消速度，物理更新被关闭后无法持续爬升。

在公共重绑定入口保存并恢复这两个原生更新标记，补齐对应事件代理，保留原有动作、变量和状态。该入口的模板展开、未预处理及动作引用缺失分支均使用相同处理。不改变攻击状态或强制移动 Boss。

| 范围 | 结论 | 证据 |
|---|---|---|
| 剧情诺斯克爬升 | 已复现并修复 | 原生状态、速度采样与修复后跨越台阶 |
| 其他使用物理／延迟更新的 FSM | 相同清标记路径已修复；未逐 Boss 验证 | 公共重绑定入口与原生速度／延迟平移夹具 |
| 模板及克隆引用 | 既有短检查覆盖 | 两种预处理初值的模板展开、激活与克隆 |

## 验证范围

本次按用户要求限制在构建、5 项相关核心检查和原生双端短测，不跑房间矩阵。开发观察和中间修复运行保留在 `.analysis/nosk-stall-fix-20261022` 与对应独立测试目录。一次新增 Smoke 夹具编译失败因误用 `GetPosition.lateUpdate` 字段，已改用本版真实存在的 `TranslateV2` 动作；失败日志保留。

最终双端检查包含：

- 真实 UDP 双端进原生剧情诺斯克场景，使用原生变身、攻击和地形碰撞。
- `Climb.HandleFixedUpdate` 在网络准备前后保持开启。
- 自然攻击期间冲刺不在平台边缘长时间静止，向右冲刺跨越左侧台阶。
- 客机显示移动的权威副本，本地原始 AI 保持停用。
- 直接调用公共重绑定后，原生 `SetVelocity2d` 与 `TranslateV2` 在后续物理／延迟更新中继续执行。
- 既有模板展开及克隆引用检查、严格双端日志检查。
