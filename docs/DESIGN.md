# 协作状态设计

## 网络与状态权威

HKMP 的 UDP / DTLS 连接承担所有数据，无附加 TCP 旁路。首个进入房间的客户端模拟敌人，其余客户端使用由引擎禁用自主 AI 的副本，接收位置、动画和动作数据。服务端验证怪物数据的发送者确为当前房间权威。

DTLS 监听器按远端 IP 和端口隔离握手队列，每个握手拥有独立 TLS 上下文，仅共享不可变证书。失败握手不停止监听器。消息集合发送和接收使用同一集合结构，避免将集合头误解析为单条业务消息。

0.1.8 使用 HCF2 数据报标识，携带消息编号、总长度、分片索引和数量，单片不超过 1200 字节。完整更新包使用 32 位长度，逻辑包最多 1 MiB，避免复杂 Boss 的动作及快照受到旧 64 KiB 限制；组件自身长度与 addon 子包仍使用各自的有界格式。每个 DTLS 会话独立重组；缺片消息不会与下一个心跳拼接，支持乱序和重复。待重组消息最多 16 条、2 秒过期，完成编号缓存最多 128 条。更新层原有可靠数据重发继续生效。旧协议不兼容，所有玩家必须同时升级。

开服成功后递增服务端代数，协作模块用代数识别同一帧的停止与重启，并丢弃旧代排队事件。停止时先取消并等待接收处理线程，再清客户端、socket 和队列；重复停止安全，绑定失败不会标记已开服。连接数据的 ChunkSender 等待旧工作线程退出、清空待发队列，每块数据重新清确认位，避免重连后确认计数与标记不一致造成无限查找。

0.1.5 将客户端每次握手隔离为独立 DTLS 对象，取消发生在工作线程启动前也有效；握手只使用自己的资源引用，断线后不能重新发布旧 transport。连接、接收与超时回调核对会话代数，排到 Unity 主线程的普通及 addon 回调在旧会话结束后失效。服务器拒绝连接也执行完整断线清理。连接数据的 ChunkReceiver 校验块编号、片编号和长度，完成状态在回调之前提交，回调内重置不会被旧完成流程覆盖。

怪物的线协议额外携带场景名、进入场景的访问编号和全队重试编号。每次切房间递增访问编号，每次全队失败递增重试编号；发送缓存按这三个值隔离。同一房间再次进入也属于新访问。丢弃旧访问、旧重试和非权威更新。服务端对离开、进入、快照、怪物更新和缓存清理使用同一个锁，避免 UDP 接收线程与全队重试清理同时修改快照列表。

0.1.9 先初始化角色、提交初始实体快照，再应用协商期间收到的实时变化；晚加载实体同样先处理基准快照。房间级 ID 0 消息无需实体实例即可重放。每次访问只提交一次初始实体快照，提前收到的权威移交作为更新的基准，旧初始快照不能把接管者恢复为副本。服务端快照深拷贝 FSM 字典、组件数据和缩放，排队后不会继续随缓存变化。

玩家进房、离房、位置与动画携带场景、重试编号、接收者访问编号和发送者访问编号；服务端验证来源，客户端验证双方访问。重复进房不重建当前人物，同一次访问的离房不能被更晚收到的旧进房撤销。进房前收到的位置、朝向和最后动画帧有界缓存，创建人物后应用；历史攻击特效不重放，换房和断线清缓存。地图位置仍允许跨房更新。原生入口回调遗漏时由已就位角色补发，每个 Unity 场景 handle 只发布一次；连接已加载房间时显式完成当前场景注册与发布。

0.1.7 静态实体使用场景、类型、FSM 与命名层级路径的 64 位散列身份，命名路径只计算同名兄弟的序号。动态对象使用独立高位命名空间，每次池化生命周期生成新 ID；退役旧 ID 后拒绝迟到更新。生成描述包含确切来源 ID、实际动作与预制体、出生坐标；副本不重新执行远端生成动作。路径引用直接沿本机场景层级查找，避免对全部已加载对象反复扫描。仍须实机核对同名同父对象本身数量不同的情况。

## 血量与死亡

0.1.8 按 Unity 对象 ID 分派 FSM 动作和查找实体归属，避免每个动作广播给全部弹幕、每个引用扫描全部实体。Release 不生成高频调试文本；FSM 变量与战斗子树每秒最多采样 20 次，仅变化才发送。子树快照覆盖根物体世界旋转、中间父节点的激活/位置/旋转/缩放，以及子碰撞器几何、DamageHero、渲染/透明度/材质颜色、tk2d 子帧和粒子启停。根动画与位置沿用原通道，独立实体子树各自管理；快照有节点/组件/数值上限和有界层级刷新。

副本在未激活的临时父物体下创建，关闭自主 FSM 与运动控制，保留零速度、零重力的 Kinematic Rigidbody2D 以参加原生碰撞。副本不执行原生受击位移；命中表现与权威位置共同驱动。入口协商期间的原生广播事件缓存到对应实体，权威确认且 FSM 能接受时重放，副本丢弃，避免战斗启动事件丢失。

原生 ObjectPool.Spawn 与 CreateObject 的实际结果全连接只观察一次，延后到原生设置完成再登记；初始隐藏物体也有明确生成记录。描述包含子 FSM 路径和初始激活值，收藏家 SpawnJar 使用实际 enemyToSpawn。回收/销毁终结整条动态生命周期并清理动作协程；切房回收旧房全局池弹幕，防止跨房累积。接管先应用缓存物理状态，再恢复 FSM；持续动作依据原生 everyFrame 字段和特殊等待/碰撞动作恢复，初始化仅重绑本机引用与组件。

血量是绝对值，附带每个敌人的版本号；变化时发送可靠更新，每秒补发一次。客户端和服务端快照缓存均拒绝旧版本；血量同时写入显示副本和停用的原始副本。死亡是带版本的终结记录，迟加入者不会重新看到活敌人，也不重复获得迟加入死亡产生的吉欧。

`hasSpecialDeath` 的零血属于多阶段 Boss 的阶段转移，不记录为终结死亡；可靠阶段事件、FSM 和阶段字段共同镜像它。HealthReset 必须有更新的明确版本，普通 HP 包不能打开死亡墓碑。额外伤害镜像原生事件，HP 按绝对值同步，不在副本重复扣血。主机交接使用包含血量、死亡、阶段字段、FSM 本机引用及生成记录的快照；接手者应用后才恢复模拟。房间无人时清空临时状态，允许原版重生规则继续生效。

神居完成由房间级 BossSceneController.EndBossScene 同步，包含附加 Boss 场景及空 bosses 数组的脚本完成。完成消息携带实际行程、序号、束缚、门和挑战 tier，恢复本机原生上下文后结束；倒地/加载/重试/个人回椅期间等待就绪。原生 TrackSpawnedEnemies 列表、附加 Boss 场景选择和音乐均作为房间状态回填。不通过零血猜测或强制下一房绕过原生战斗完成。

FSM 观察钩子先执行原生动作，仅隔离同步观察者自身的异常，并继续其余观察者；原生动作错误照常传播。动作实例被 PlayMaker / 神居逻辑替换后，在执行时按当前 FSM、状态和动作槽重新绑定，不继续依赖失效的旧实例。已销毁的注册对象、SetScale 目标与碰撞显示副本不再被解引用。火球的显示副本移除 GrimmballControl，碰撞、缩小和回收由权威结果驱动；Firebat Pillar 作为单独实体同步。

某些 FSM 在 Idle 而非 Init 绑定 GetOwner 引用。副本初始化和接管时恢复本机 GetOwner，并同步 GameObject 变量的实体/场景路径/hero/空引用；未生成的依赖可有界等待后重绑，预制体资源保持本机引用。初始化跳过生成动作，不在副本重放历史弹幕。动画、回收、激活与伤害钩子统一注册，按对象分派，避免对象池循环反复重建原生 detour。

## 共享进度

与 HKMP 原有的整存档同步分离。开房使用各自存档，通过白名单的单调账本合并永久能力：布尔值只从 false 到 true，等级只增不减。取最大值替代加法，因此消息重发、两个玩家重复获取同一能力和迟加入均不会多发一次能力。消费型字段和可往返计数不放入账本。

共享规则取房主开房时的配置。每个会话拥有随机 session ID，断线重连清理本地授权账本，避免旧房间的授权污染新会话。实际已经写入本地存档的能力按正常游戏进度保留，并可加入新会话的进度并集。

## 救援与全队重试

成员状态是 Loading、Alive、Down、Resetting、Returning。死亡事件可靠携带准确的场景和死亡坐标；Down 期间心跳只刷新时效和对应位置的地图坐标，不能改变死亡位置或复活角色。倒地编号拒绝旧救援，生命周期版本拒绝旧位置列表把已经救起的人重新显示为倒地。

客户端截断正常模式的原版死亡流程，在死亡点固定角色位置、停止物理模拟并隐藏角色渲染，保存并冻结相机模式与位置。单独创建仅含原生 Hollow Shade 的 tk2d 外观、Idle 动画和命中盒的救援暗影；不复制 AI、FSM、掉钱或回收灵魂逻辑。暗影视觉轻微上下浮动，逻辑死亡点保持固定。

活着的本机角色用骨钉实际命中救援暗影时，IHitResponder 经游戏 HitTaker 收到命中；排除远端攻击副本、敌人攻击及死亡角色，然后可靠发送 ShadeHit。服务端校验同场景、双方状态、位置时效、死亡编号和 5 单位距离包络（兼容骨钉长度护符与近期移动），授权一次 Revived。收到授权后播放原生暗影 Death 动画、恢复角色与相机，在原处设为 1 格血、0 格蓝血。无需按键或持续靠近；重复命中、旧死亡轮次、全队重试期间的命中均无效。离线、切场景与全队重试时清理暗影并恢复渲染状态。

临时倒地不激活 heroDeathPrefab。致命攻击已经播放本机受击声时不重复播放；其它致命路径补一次原生 HeroSounds 受击声。可靠 Down 对所有在线队友播放一次声音，同房间复制原生 Hit Pt 粒子，最多 16 粒、实际发射 12 粒、缩放 0.7、寿命 0.45 秒，1.2 秒真实时间后清理。生命周期排序与反馈编号分别维护，列表先于可靠事件到达不会漏反馈，旧事件不覆盖复活状态。远端 Stun 动画携带临时倒地标记，避免再播放一套完整受击声和粒子。

所有成员都 Down 才触发全队失败。服务端只推进一次重试编号并清理怪物缓存，冻结每个人自己的复活目的地。客户端启动倒地时捕获的原版 HeroController.Die，保留原生死亡动画、吉欧池、暗影放置、灵魂限制、易碎护符和特殊地图区域分支。目的地、标记、类型、朝向和梦境返回字段均来自本人；不计算替代处罚、不统一到主机长椅。抵达正确目的地、角色就位、场景切换完成且镜头不再冻结后逐一发送 Ready，所有仍在线成员 Ready 后服务端发 Release。断线移除等待成员，迟加入者使用自己的检查点而不补收死亡处罚。

客户端记录已 Release 的轮次，迟到或重放的同轮 Wipe 不会再次进入重试；迟加入但尚未 Release 的玩家仍可加入当前屏障。回检查点与传送的协作协程在断线、新轮重试及销毁时取消；等待流程同时检查会话与轮次。已经被原生引擎接受的跨房加载不能通过停止协程撤销，因此其临时入口保留到原生抵达完成，保证断线后也能淡入；抵达后的队友重新定位操作取消。加载超时只提示并继续等待，抵达指定场景且角色就位后才发送 Ready，防止在旧房间错误解除屏障。

死亡玩家按 F6 可靠发送 GiveUpRequest，携带本次死亡编号及自己的最新长椅场景、标记和 respawnType。服务端仅允许对应 Down 状态转换为 Returning，冻结个人目的地，并广播 Returning；救援和主动放弃按同一服务器队列顺序处理，仅先成功者生效。全队已经 Down 时拒绝个人放弃，由统一失败流程处理。

F6 同样接受一次本机正式死亡，使用原版 Die 和该玩家的个人死亡上下文。它不推进重试编号，不清理服务端怪物缓存。Returning 期间移除救援暗影、隐藏地图坐标并拒绝救援和传送；原版动画和个人加载完成后发送 BenchReady，服务端校验死亡编号及实际抵达场景，Returned 后恢复控制。到达确认推进位置序号，旧房间心跳不能覆盖到达位置。原房间仍有玩家时保留战斗，回椅者是房间权威时正常移交。原版死亡协程由 HeroController 持有，停止协作等待或断线不会取消已经接受的死亡。

房主的 EntryProtection 规则随 Welcome 发送。每次场景 handle 或连接会话变化建立一次入场保护；依次等待原生就位、进门移动完成（非 transitioning，transitionState 为 WAITING_TO_TRANSITION）、无协作加载/倒地/返回、接受输入、非死亡、非暂停、非冻结镜头以及本次访问/轮次快照提交，再连续保留 1.5 秒。保护期内重新失去就绪条件会重新计时，已经结束的保护不能因战斗失控重新启动。普通攻击在 TakeDamage 前拦截；地形危险保留原生恢复，在 AfterTakeDamage 把伤害设零，避免免伤导致玩家滞留尖刺或酸液。

## 定位与传送

地图投影沿用游戏指南针的房间图块、场景宽高、原点偏移及室内入口映射。所有输入验证为有限数，场景尺寸为零或找不到房间图块时返回无坐标，不复用上个房间坐标。在线玩家心跳用于定位与方位，与地图探索字段无关。未知地图区域以房间名呈现。

传送目标由服务端根据目标玩家的最新可信会话记录决定。跨房间使用临时入口钩子，不修改梦之门字段；抵达后检查地形碰撞，再应用最新目标位置并重设危险重生点和相机。其安全落点与 Boss 房门交互仍需实机覆盖。

原生梦之门入口只负责角色抵达，配套梦之钉 FSM 才负责淡入。F8 没有运行该 FSM，因此 0.1.6 在限定的临时入口抵达时完成淡入、相机定位与控制恢复。普通梦之门流程保持原生行为。神居目标额外携带连战资源名、序号、门和绑定规则，载入目标前恢复本机连战上下文；离开连战前往普通房间则恢复绑定并清理本机上下文。无法解析目标资源时在加载之前提示。
