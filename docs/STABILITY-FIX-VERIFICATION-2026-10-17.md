# 双端卡死、共享奖励与流畅性修复记录

前一轮全量审计和失败证据保留在 `FULL-DUAL-DETECTION-2026-10-17.md`。本轮复测均使用 `.test-results/game-host`、`.test-results/game-guest` 和被拦截保存的内存角色，不读写真实存档。每次运行使用新目录，保留失败证据。

## 实现

- `CombatStateComponent.Parts.Refresh` 处理 Unity 已销毁对象的假空引用，清空组件缓存；层级重建接受缺少 Host 的节点。新增实际 Unity 对象销毁夹具，直接执行 Refresh、Build 和 Tick。
- 地图坐标与传送就绪状态分开；短暂投影失败只使用同房间、同地图实例、1.5 秒内的坐标。传送继续要求双方原生控制就绪，不能用地图坐标绕过长椅、商店或过场限制。
- 房主的 `SharedResources` 保存房间累计来源；`Resources` 仅表示本机已发奖。客机领取不会提前把房主标为已发奖，旧存档从本机回执单向迁移权威历史。
- 资源按来源排队，原版领取动画串行完成后处理下一项；商店旧确认框保留原版动画和标记，但重复来源不再扣钱。
- 面具/容器碎片共享调用预加载的原版获取动画，在接收者当前位置播放；远端播放不写本地商店/场景物品的已拾取标记。
- 重复本地动画同时拦截碎片写入、碎片归零和整块上限结算，避免“数值拦截了但动画又加一次上限”。普通矿石消费和真正首次转换保持原版行为。
- 无原生模板时的数值补发保存全部相关字段快照，失败回滚；表现回调与发奖提交分离。失败重试至少间隔一秒，同一来源不逐帧刷日志。
- 调试采样从每帧改为每 0.5 秒；服务器来源扫描每 0.25 秒。复用 GUI 样式和地图清理列表，正常界面只在重绘时绘制，避免每帧复制队列与重复创建样式。
- 白色防御者入场恢复避开死亡、全队复位、个人返回、原版加载、长椅和原版暂停锁；单人/断线仍可运行。F9 面板及诊断导出可用于采集旧坏档现场。
- 支持的 FSM 动作钩子在连接阶段安装，战斗内只更新对象订阅；注册表预先展开，查询对象名称时只跨一次 Unity 原生边界。
- 原来的投射物登记每 100 毫秒集中执行，改为逐帧 FIFO 队列；房主登记与客机重建分别采用约 2 毫秒批处理预算。每个对象完整处理后再让出，单个对象本身可能超过预算；入场基础快照仍完整提交。场景/轮次和销毁回执继续校验。
- UDP 发送批次在锁内取出、锁外编码，下一批位置/战斗更新不再等待编码；发送顺序与原生状态事务仍由发送锁保护。编码失败会把可靠内容保留到后续载体。
- 修复未激活模板 FSM 的占位状态表：实际召唤物可能同时满足 `Preprocessed=true`、状态引用有效，却仍只有默认 `State 1`。登记前展开这种占位模板；已展开的原生实例只预处理本机动作，不重建模板。准备后的未启动实例脱离模板，首次原生 Awake 不再替换已订阅状态机。已经运行的原生模板不脱离。

## 隐藏梦境原版路线

`stability-native-route-20261017-c-defender` 双端及严格日志通过：原生粪便骑士死亡结算 → 两端离开并重进、不再刷出存活 Boss → 运行原版 Quake Antic/下砸与地板碰撞 → 原生场景门进入 `Waterways_15` → 注入梦钉按键，经真实攻击碰撞和 Dream Enter FSM 进入 `Dream_04_White_Defender` → 原生入场恢复控制。房主先入梦，客机随后入梦。测试明确设置了三梦者与熟睡的剧情前置，不读取真实档。

断线后分别注入输入、刚体和相机锁，两端均通过单人自动恢复断言，已击败 Boss 的进度保留。这是原生路线加故障注入验证，尚未直接加载用户此前损坏的存档。

该专项的 `a/b` 保留为失败：下砸入房通过，但探针的单渲染帧梦钉脉冲可能错过原版 FixedUpdate 采样；`c` 让输入持续到原生 FSM 接受后通过。没有为通过测试而跳过原版 Dream Enter 转场。

## 未激活召唤物模板的差异复现

`stability-smooth-final-20261017-a-final-native-host-013` 完成原版行程断言，但客机出现 `chaser: unknown state index 3/5, local states=1`；收紧严格日志后明确拒绝，未计入最终通过。首次仅检查 `Preprocessed` 的修正仍在 `stability-final-template-20261017-b-final-native-host-013` 被同一门槛拦下。

原版对象跟踪 `stability-template-native-trace-20261017-e` 直接记录房主 `chaser=8` / `flyer_receive_direction_msg=7`，客机两者均为 `State 1`，同时 `Preprocessed=true`、`Initialized=true`、`Started=false` 且仍持有模板。最终修正的真实召唤链跟踪 `stability-template-native-fixed-20261017-g` 记录客机登记后分别展开为 8 / 7 个状态。

夹具 `stability-template-baseline-20261017-a` 在旧构建真实失败。后续夹具覆盖占位状态的两种 Preprocessed 标记、已展开实例中的运行时变量/动作保留、首次原生激活与复制后的本机动作引用；最终生命周期双顺序用相同夹具重新验证。诊断跟踪是测试插件的可选开关，不用于性能采样。

保留未完成/失败诊断：`stability-template-native-trace-20261017-c` 的测试探针错误选中原生测试序列，未进入目标房；`d` 在召唤前改用定向采样，未完成；`e` 为保留索引异常的失败诊断。场景覆盖探针已限定选择正式 Tier 序列，不再误取 `Boss Sequence Test`。

本轮不清除 `runtime-blockers-0.1.21.json` 中历史原因未确认的项目；套件通过也不自动代表满足正式发行门槛。没有安装到用户真实游戏或改写真实存档。

## 最终性能扩展中的探针失败

`stability-final-template-20261017-h-combat-profile` 新增 `GG_Vengefly` 后，房主 30 秒窗口完成（最长帧 23.04 ms、0 帧超过 33.33 ms），客机因“必须收到压缩快照”的测试前提超时，该整组不算通过。这个较小房间的原生快照没有达到压缩阈值；探针对该房改为要求成功应用真实缓存快照，另外三个原有场景保留压缩快照要求。修正仅修改测试插件，生产 DLL 哈希不变。完整四场双端性能重跑使用独立前缀 `stability-final-performance-20261017-i`，失败目录保留。
