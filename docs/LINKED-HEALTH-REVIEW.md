# 链在一起规则审查（2026-10-28）

本轮落实用户补充的「允许卸下禁用护符」，其余条目为审查发现和设计建议，没有擅自改变玩法。静态路径、纯模型复现和实机覆盖分别记录；此前 19 组通过不代表覆盖了下述所有边界。

已修正：装备禁用护符仍被拦截，原生 `UnequipCharm` 和装备标志写入 `false` 均放行；这两种操作也会移除入房前的暂存记录，保存／退房不会重新装备。护符槽与过载按剩余搭配计算。双端专项验证了一方主动卸下、另一方保留暂存搭配，保存和退出结果均正确。

建议保持的规则：同一攻击实际命中多人时逐人累计伤害；无敌帧与护盾保护仍属于各自玩家；同帧治疗与致死伤害以服务器确认顺序为准，归零后不能用迟到治疗复活；离房不能补血，重连继承当前团队状态。

本轮验证：增量生产构建通过，12 项相关核心检查通过；4 组同机双端（卸下与保存／退出专项、模式关闭、无护符共享、无进度共享）均双端 FINAL PASS，严格日志和当前生产哈希一致。证据位于 `.analysis/linked-rule-audit/`。此前完整 19 组记录保留在 `.analysis/linked-rest/`，对应此前的生产哈希。

## 用户采用建议后的补全

上表保留最初审查状态及其历史证据。用户随后采用动作隔离、旧档碎片基线、世界蓝血保护，以及普通血量上限规则；明确选择禁用脆弱／坚固心脏并禁止生命绑定。

- 同步血条的受伤／治疗事件只投递到 HUD，不向骑士或世界广播虚假的受击；怒火读取共享血量时单独刷新。
- 初始血量只读取本机房主的已载入存档。客机初始化消息只能请求当前快照；房主的永久面具、未满碎片及已知来源分开计数，后续不同来源继续累计，永久部分最多九格。
- 自动卸符保留超出入房原生生命血护符额度的世界蓝血。模式已生效后，禁用标志注入不能再被当成实际发放过护符蓝血而扣除世界蓝血。
- 心脏（同一 ID 23 包含脆弱和坚固版本）加入双层禁用；已装备者暂存并允许主动卸下。生命绑定的原生挑战入口被阻止，正在绑定挑战中的存档不能入房。
- 存档类型按准入强制一致，拒绝两个方向的普通／钢魂混房，不修改个人类型。真实钢魂死亡保留原生结果并结束房间挑战；梦境成员完成自己的原生返回，全梦境队伍仍可重试。
- 权威零血不再先等一帧；同帧断线还有原生死亡续行保护。休息心跳携带代次，受伤后旧心跳不能重新就位，重复或乱序伤害不会反复取消新的休息。
- 休息快照包含未就位姓名，区分加载、未就位和等待响应；实际在椅子上的成员不会因传送暂不可用被误标为加载。
- 正常菜单退档原本就会断开和停服。补上的房主存档身份／档位／对象检查防止其它代码直接换档后继续使用旧房间。
- 额外血量、共享当前血量和暂存护符不进入个人保存快照。退出恢复个人基线；正常升级、复活和真实流程进度照常保存。专项通过原生 JSON 设置、临时结果目录中的快照和原生复活来验证关闭后重载，不绕过测试插件的私人存档保护。

本轮单独证据在 `.analysis/linked-isolation/`，最终通过范围以该目录汇总为准；旧表和旧哈希不追认为本轮结论。
