# 0.1.10 格林弹幕运动修复

版本：HollowConnect 0.1.10 / HKMP 3.0.0-hc7。所有玩家升级完整包，安装器仍自动发现 Steam 库或接受手选目录。FRP 配置不变。

已使用发行包内一键安装器完成本机更新；7 个安装文件与最终运行及 manifest 一致，安装前后 64 个存档文件名和哈希均未变化，最初卸载备份保留，正常游戏没有测试插件。见 [安装证据](evidence/upgrade-0.1.10.json)。

## 原因与修复范围

`CombatSpawns` 等待原生生成动作完成后登记弹幕。旧版 `Entity` 构造时无条件关闭权威原始对象，随后 `InitializeHost` 重新开启它。格林气球火球的 `FireGrimmBall.OnEnter` 已设置推力并启动 `GrimmballControl.DoFire`；关闭对象会执行 `OnDisable`、停止飞行协程与 iTween，重新开启则执行 `OnEnable`、将 force / tweenY 清零。因此两端可以同步显示同一条错误轨迹，位置一致不能证明技能正确。

0.1.9 原始安装 DLL 的[轨迹专项](evidence/baseline-grimm-0.1.9.txt)记录了原生发射时推力为 +7 / -7，约 0.08 秒后检测到推力或飞行协程丢失，生成明确失败标记。测试未强迫 Boss FSM 状态。

修复仅在“动态生成、已确认房间权威、由本机模拟”的登记路径保留原生对象启停状态。副本仍保持禁止本地模拟，未确定权威的场景对象仍等待房间状态。它是动态生成生命周期修复，适用于通过同一路径生成的其他攻击；不据此宣称其他 Boss 全部验收。

## 验证方法与边界

测试使用两份隔离的真实 Unity 游戏、内存角色、本机 UDP；音乐和音效由测试插件静音，不修改玩家设置，不加载或写入玩家存档。测试插件不进入安装包。

新增 `grimm-motion` 专项在原生 `FireGrimmBall` 执行后记录推力，并检查网络登记后的推力、飞行协程和沿原生发射方向的横向位移。另检查火蝠横向飞行、副本刚体无重力和本地速度、移动弹幕的双端位置。双方正常断开后才停止服务器；任一失败标记均判失败。每轮生产 DLL SHA-256 与最终发布文件分别比对。

实际已完成的运行见 [专项记录](evidence/runtime-grimm-0.1.10.json)，自动化回归见 [97 项记录](evidence/regression-0.1.10.txt)。普通格林两种先入顺序、梦魇格林正常入场与客机先入后延迟 15 秒加入，以及普通格林离房接管后重新加入，共 5 组双客户端运行通过。接管后新权威有 72 次保留推力和横向运动的火球样本、18 个横向飞行火蝠。

梦魇格林的首次 15 秒延迟入场运行没有取得足够有效弹幕样本，双方失败；增加状态、站位和样本诊断后的复测记录 72 次有效火球发射并通过。首次失败原因尚未确认，保留于运行汇总，不能删掉失败轮次或据复测声称迟入场绝无问题。原生批处理启动 / UI 清理告警和正常断开时的 UDP ConnectionReset 警告也不称为“日志零异常”。

该专项验证原生发射与运动及副本物理约束，不等于全部招式、全阶段伤害、普通流程奖励或两台机器 FRP 验收。接管专项在气球火球一轮结束后离房，未验证飞行中弹幕的脚本状态恢复。
