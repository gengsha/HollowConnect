# HollowConnect 0.1.22

新增隐藏紧急回椅快捷键 **Ctrl+Alt+F12**。载入卡住的存档后，按住 Ctrl 和 Alt，再按 F12；左右修饰键均支持，无需打开菜单、联机或恢复人物控制。它会断开本机联机，回到德特茅斯长椅，确认原版长椅与角色就绪后自动保存。看到完成提示后可起身继续游戏，或重新开房。

快捷键将当前存档的复活点改为德特茅斯长椅；不调用死亡流程、不扣吉欧、不清个人暗影、永久能力、Boss 击杀和共享资源回执。若原版场景加载已开始，先让该加载安全完成，再返回长椅，避免强行丢弃 Unity 异步加载造成第二次卡死。连续按键不会同时启动多个回椅流程。主菜单不触发；进程完全冻结、没有运行更新循环时无法接收快捷键。

本版同时包含此前完成的白色防御者梦境入场恢复、粪便骑士离房重进进度、房主存档共享来源记录、资源去重及原版领取反馈、模板 FSM 初始化和流畅性修复，以及 F9 诊断工具。细节与覆盖边界见 [稳定性修复记录](STABILITY-FIX-VERIFICATION-2026-10-17.md) 和 [死档风险审计](DEAD-SAVE-AUDIT-2026-10-17.md)。

关闭游戏，完整解压 `HollowConnect-0.1.22-windows.zip`，运行 **一键安装.exe → 安装 / 更新**。房主和队友都使用本次同一完整包，再重新开房。菜单显示 **HollowConnect 0.1.22 / HKMP 3.0.0-hc11**；FRP 配置沿用。

打包前的最终功能构建已通过 200 项核心回归及 `emergency-bench-20261017-e` 双端专项：两端共 6 次回椅，覆盖暂停与控制锁、真实梦境加载阻塞、离线死亡状态；每次均检查新场景的原版长椅、起身操作、进度与资源保持，以及坐稳后的一次保存请求。主菜单残留存档编号、缺少修饰键和连续按键也已检查。测试使用同机两个隔离进程及内存角色，保存写盘被拦截；没有加载用户的真实坏档，也没有验证真实存档写盘后重新读档。

用户随后明确要求“不检查了，直接打包新版”。剩余普通流程双端复测已停止，未记为通过；0.1.22 仅升版编译和打包，不重跑游戏或回归。之前的通过记录保留实际 DLL 哈希，不能当作本版新 DLL 的完整运行验收。见 [回椅专项证据](evidence/emergency-bench-2026-10-17.json) 和 [本版打包记录](evidence/runtime-room-0.1.22.json)。历史未解问题继续保留在 [问题账本](evidence/runtime-blockers-0.1.22.json)。
