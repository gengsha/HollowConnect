# 愚者试炼左右墙双端复现

后续已授权实施修复，进展与新构建的验收单独记录在[修复报告](GOLD-WALLS-FIX-2026-10-22.md)。下文保留修复前的复现结论和原始哈希。

2026-10-22，已复现反馈的核心现象：第三档愚者试炼原生第 30 波左右墙内收时，场景权威端具有墙体渲染和实体碰撞，另一端缺少这两堵墙，墙所在位置没有实体碰撞。交换先入场顺序后结果随场景权威交换，房主和客机均可成为缺墙的一端。这是已确认的问题。

尚未独立切换敌人的仇恨目标，因此不能断言仇恨切换直接导致墙体消失。当前证据确认的是“跟随场景权威”。本次仅复现、定位，未修改生产代码、升版、打包或安装。

**实机结果**

使用既有 `game-host` / `game-guest` 隔离副本，真实 localhost UDP，第三档、共享开启、无网络故障注入，串行执行。经原生报名牌、实际入口和开战触发进入；最终两组经原版敌人死亡回调推进到第 30 波，停止伤害并等待原生 `MOVE` 和墙体位移动画完成。两侧 `Distance=12`，碰撞中心从约 x=80.78/123.88 内移到约 x=92.76/111.99；另一组因原版震动位置略有不同。

四组均双端完成、严格日志通过、生产 DLL 哈希匹配。`observed`／done 表示诊断完成，产品结果为缺陷复现，不代表墙体功能通过。射线起点取权威端实际墙碰撞中心左侧 3 单位、y=14，向右 6 单位；两端使用相同坐标，过滤为非触发器的左右墙碰撞体。

渲染器数量指 active、enabled 且非 forceRenderingOff 的组件，不等于相机视锥可见数量。原始相机截图已保留并检查，但 batch 模式画面较暗，仅作辅助；缺墙结论依赖实际对象树、渲染组件、实体碰撞体和物理射线的交叉证据。未以第一波尚在视野外的墙截图替代收缩阶段验证。

**原因定位**

| 证据 | 含义 |
|---|---|
| `src/HKMP/Resource/entity-registry.json:1053` | `Colosseum Wall` 及子对象 `Wall` 均标记为 `networked:false`。 |
| `src/HKMP/Game/Client/Entity/EntityRegistry.cs:24`；`LocalWorldIsolation.cs:10` | 墙被视为个人本地屏障，排除独立网络登记。 |
| `src/HKMP/Game/Client/Entity/Entity.cs:237`、`:413` | 竞技场管理器复制时，`DestroyManagedChildren` 又按登记名称删除复制层级内的左右墙。 |
| 双端 `*-walls-contracted.json` | 非权威端原管理器的墙仍存在但父层级未激活，活动的 `Colosseum Manager(Clone)` 内没有左右墙；权威端使用原管理器，墙正常运行。 |
| `src/HKMP/Game/Client/Entity/LocalBarrierEvents.cs:17` | 本地屏障还会忽略重放事件；后续修复不能只补显示而忽视原生墙体移动和碰撞。 |

这些代码路径与实机观测一致：墙既未保留在活动复制层级中，也未作为独立同步实体恢复。此处记录定位结果，没有应用修补。

**保留的失败及测试边界**

早期 r1 停在第 22 波，旧伤害循环触及后续波次的休眠怪物；r2 避免该问题后停在第 23 波隐藏小怪，测试角色未接近；r3 接近后剩余一只停在 `Check Saver`，原版要求角色离开出生保护区。最终 r5 测试逻辑在触发出生后移开测试角色，保留原版检测，不强发出生事件或强置 FSM。另有 r5 运行因使用旧 Windows PowerShell 的模块路径不兼容，在游戏启动前失败，r6 改用当前 pwsh。上述记录均保留，不计作墙体复现验收，未反复原样重跑。

测试角色免伤、悬空并调整站位，终结伤害通过原版 `HealthManager` 回调；不强置波次、敌人数、墙 FSM、墙坐标或 `MOVE`。仅验证第一波和第 30 波这一收缩边界，没有验收完整第三档通关、收缩中断线接管／重连、实机跨电脑或 FRP。仇恨目标未独立控制。
