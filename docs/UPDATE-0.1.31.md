# HollowConnect 0.1.31

2026-10-22。测试渠道，`releaseReady=false`。引擎仍为 **HKMP 3.0.0-hc12**，附加网络标识 **0.1.31-l4**；房主与所有队友须更新同一个完整包并重新开房。

## 本次变化

- **流程暗影落位整改，神居落位算法保持原样。** 普通流程、梦境 Boss 和封门战斗优先死亡侧真实支撑；致命地形回溯本次访问中真实走过的安全路径。校验身体空间、地面和救援挥钉位置；倒地后持续重验，平台失效时可靠迁移。确实没有安全落点或明确封门隔离时按原版个人死亡返回，避免留在无法救援的位置。范围及较早构建的路线实测见[流程整改记录](STORY-RESCUE-FIX-2026-10-21.md)。
- **主动放弃按观战开关处理。** 暗影形态按 F6，开启观战则直接观战，关闭则回个人原版复活点；已经观战时再按 F6 可提前返回。
- **Boss 结算免费复活。** 真正击败后，本场暗影／观战者可在同场原始存活参战者处一血复活，不消耗救援次数，额度耗尽也能参与。骨钉救援次数仍仅在成功救起时扣除、真正坐椅子时恢复；剩余次数提示只在消耗后显示 4.5 秒。
- **保留各自原生结算。** 复活后参与个人奖励、封门解除、神居下一面和结局；神居推进等待结算回执，避免先换面丢下队友。没有同场原始存活参战者时不凭空复活。
- **修复观战镜头闪回。** 被观战队友受伤时短暂进入不可传送状态，镜头仍跟随有效同场队友，不在死亡点与队友间反复切换。
- **修复五门失败冠军、纯粹容器倒地镜头偏移。** 暗影落点已在当前战斗画面内时保留实际战斗视图，神居落位查询和坐标算法不变。
- **修复末场原生结局分歧。** 无上辐光实际启用的最终过场标记此前未同步，导致房主进入结局 D、加入者误停空入口场景。现在严格限定同步这项末场标记；升版前暗影、观战和全程存活三种加入者状态均双端进入原生 Ending D。空洞骑士剧情末场另修复迟到入口战斗重启、打断复活者聚集的问题，保留各人原生遗体与结局。

此前的无眼、共享资源、失败冠军登记、戈布离房清理、存活队友索敌与紧急回椅功能继续包含。已有房主设置保留，修改房主规则后重新开房。

## 验证与包装

升版前最终生产构建的 **253 项核心检查、39 组双端游戏用例通过**，含 12 项房间生命周期矩阵、两种剧情结局参与、三种五门末场参与、救援规则、免费结算和镜头。逐组结果、真实失败及修正、生产哈希见[结算整改报告](SETTLEMENT-RESCUE-2026-10-21.md)与[原始证据](evidence/settlement-rescue-2026-10-21.json)。较早流程落位构建的 28 组路线／故障、17 组相关回归、12 组房间检查保留在其独立证据中；不能把不同构建和重叠检查相加为本版完整实测。

本次打包仅把生产显示版本从 0.1.30 升至 0.1.31，增量构建并核验安装包、源码包和校验和，未新增核心或游戏回归、未运行安装器安装个人游戏。升版前受测 DLL 已另存；新 DLL 哈希、构建日志及旧验证引用见[本轮包装记录](evidence/runtime-room-0.1.31.json)。旧哈希的游戏通过不冒充新 DLL 的运行验收。

测试边界仍为隔离副本、临时内存存档与本机 UDP。完整连续五门、片尾后重新载入、原截图位置移动／交互、所有 Boss 全阶段、三人、双机 FRP 和真实存档写盘重读未被这些记录覆盖。保留的历史未关闭记录和间歇压力异常见[当前问题账本](evidence/runtime-blockers-0.1.31.json)；后续通过不自动关闭原因未定的历史报告。

## 安装

关闭游戏，完整解压 **HollowConnect-0.1.31-windows.zip**，运行 **一键安装.exe → 安装 / 更新**。所有队友使用同一新包并重新开房；无需卸载或重建存档。
