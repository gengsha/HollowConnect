# 放弃、观战与 Boss 结算复活

用户确认：结算复活不消耗救援次数，额度耗尽的观战者也能复活。本文更新同日早先的规则记录；原报告、失败日志和旧二进制证据继续保留。

| 操作／事件 | 当前行为 |
|---|---|
| 暗影中主动放弃，观战开启 | 可靠请求经服务器确认后直接观战；不走个人死亡，不改变死亡序号，不消耗次数。 |
| 暗影中主动放弃，观战关闭 | 保留自己的原版死亡／复活点返回。 |
| 已经观战时再次主动退出 | 保留提前返回自己的复活点。 |
| 真正 Boss 击败 | 本场暗影／观战者一血复活在同场原始存活参战者处，不扣救援次数；没有原始存活参战者时不凭空复活。 |
| 神居下一面 | 等待本场结算请求处理后执行原生推进；保留原生序列索引与入场流程。 |
| 剧情战利品、封门与结局 | 复活后由各人的本地原生流程处理；不把队友的奖品领取记录或结局选择复制过来。 |
| 骨钉救援次数 | 仅成功骨钉救起时扣除，真正坐椅子恢复；下方剩余次数仅在消耗后显示 4.5 秒。 |
| 观战队友受伤 | `Loading` 只表示短暂无法传送，也可继续观战；仍校验同场、存活、新鲜状态和实际活动头像。 |
| 神居暗影落位 | `FindLegacyRescuePosition` 方法体保持原样，仅规范化换行后进行等价核验。 |

Boss 胜利凭证绑定房间、各玩家的实际场景访问、当前回合与死亡序号。复活只选择凭证中的原始参战者，并再次核对服务器的实际场景访问和新鲜位置。已接受返回、旧访问、重复凭证、过期消息和后一次死亡不能复用此前结算。

原生神居完成消息和复活通知可能分开到达。场景权威和收到完成消息的加入者都保留结算等待，直到服务器收到各参战者的结算回执；离场、返回与断线不阻塞其余玩家。凭证 15 秒到期，客户端等待也有上限，避免丢失上下文造成永久等待。

镜头调整仅在暗影落点已处于画面内时保留实际战斗视图，避免倒地时无条件 `PositionToStart` 重新居中。屏外暗影继续使用现有场景边界定位。此项没有修改神居的地面查询或暗影坐标。

网络兼容标识为 `0.1.30-l4`，显示版本仍为 `0.1.30`。新增观战请求／确认和结算完成回执，要求双方使用相同构建。

关闭永久进度共享时，实际参战者也需要本场 Boss 自己写入的击败标记，才能在返回后领取自己的奖励。复制范围限于原生 Boss 击败状态中启用且设为真的 `killed*`／`defeated*`／`*Defeated` 布尔标记；奖励已领取、梦之精华、计数和任意剧情变量不复制。瞬时击败状态可能在同一网络帧被后续状态覆盖，因此通过已有可靠动作流保存实际执行事件，并保留最新状态的补记。神居排除在这项剧情补记之外，空洞骑士继续使用既有个人遗体与结局流程。

无上辐光在最终斩击后还有原生过场，因此允许其已确认的最终击败标记在 `Final Impact` 时开始本场结算，供倒地／观战者在最终过场前复活；仍保留原版最终斩击、过场输入与结局选择。

空洞骑士剧情结局的迟入参与者可能仍有本地 `Boss Control/Battle Start` 停在 `Revisit`。结算复活后靠近遗体会触发迟到的吼叫、取消聚集并重新开启战斗。现仅在收到权威 `Phase Control/Die` 和活动、脱离父级的遗体状态两项证据后，停用本场该入口 FSM；个人遗体仍完整执行原生落地、聚集吸收与各自 A/B 结局。没有对神居入口或其他场景采用此处理。

2026-10-22 的五门末场探针确认：`Control/Ending Scene` 中旧的 `CallMethodProper(ChangeToScene)` 已被原生资产禁用，参数还保留剧情结局 C，不能把它当作五门执行路径。实际启用的是 `SetStaticVariable(ggCinematicEnding=true)` 和 `EndGGBossScene`。此前该标记没有同步，双方虽都在五门上下文中，加入者仍停在空入口的 `GG_End_Sequence`，房主则经本地 `Dream Return/Change Scene` 进入 `Cinematic_Ending_D`。现只同步 `GG_Radiance` 无上辐光 `Control/Ending Scene` 实际启用的这一正值标记，并允许已验证的终态快照补记；任意静态变量及方法调用不放行。原生返回控制器负责消费该标记并按本地条件选择 D/E，测试必须检查实际结局场景，不能仅以离开战场作为通过条件。
