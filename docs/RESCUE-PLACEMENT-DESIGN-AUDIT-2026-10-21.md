# 流程战斗中暗影无法接近：救援落点设计审计

2026-10-21。用户收到跨普通 Boss、梦境 Boss 和部分流程战斗的广泛反馈，补充描述为“几乎所有”。当前没有具体场景或现场状态，不能把广泛反馈写成已经逐场复现。本轮确认的是通用实现和验收标准的缺口，没有修改生产代码或运行新游戏测试。

## 结论

现有规则把正式死亡后回收暗影的位置、危险地形复位点用于即时队友救援；验证了候选点的局部支撑与碰撞，没有验证活着的队友能否接近并实际挥刀命中。神居的相对单纯场地容易通过这种验证，流程场景的封门、分区、垂直结构及阶段地形会暴露问题。现有流程测试也存在绕过救援路线的夹具操作。

这足以确认为系统性的设计风险，需要统一修正落点策略与验收标准。尚不能据此认定每个 Boss 都发生了同一种错误，也不能把所有“救不了”反馈都归结为地形：现场还应区分暗影位置不可达、实际碰撞未命中，以及命中请求被服务器拒绝。

## 确认的实现缺口

| 编号 | 当前实现与证据 | 可能后果 | 置信度 |
| --- | --- | --- | --- |
| RESCUE-POS-01 | `CoopRuntime.FindRescuePosition`：普通流程的非危险致死先选最近 `Shade Marker`，成功就返回；死亡点在最后才尝试（751、775–782 行附近） | 正式死亡后方便独自回来回收的点，可能位于当前封闭战场外。场景相同、地面有效，仍然救不到 | **confirmed static risk**；具体现场未复现 |
| RESCUE-POS-02 | 梦境、白宫、神居跳过正式暗影标记后，优先 `hazardRespawnLocation`。仅 `Dream_04_White_Defender` 有优先死亡点侧落地的特殊规则（770–781 行附近） | 危险复位点可能属于进入战斗前的门外或旧区域。白色防御者注释已经明确描述这种问题，但修补只覆盖该场景 | **confirmed static risk**；不能推断全部梦境都受影响 |
| RESCUE-POS-03 | `Ground` 向下查询最多 50 单位，`TryWarpLanding` 检查脚下支撑、角色体积、伤害碰撞及小范围偏移（751、1019 行附近） | 地面可站立，不表示与队友处于同一个可达战斗区域。长距离向下投影也可能落到下层独立区域 | **confirmed static risk** |
| RESCUE-POS-04 | `ShadeService.Ensure` 只在创建时写入位置；暗影静止、无重力。倒地后没有主动修复失效落点，支撑复查发生在收到救起确认后（`ShadeService.cs:42`；`CoopRuntime.cs:441`） | 平台移走、地板破坏、阶段切换后，暗影可能仍悬在旧坐标；队友还没打到暗影，就无法触发后续复活落点复查 | **confirmed static risk**；原生动态场景仍需验证 |
| RESCUE-POS-05 | `Party.Presence` 不更新倒地者的位置，`Down` 拒绝已经倒地的成员；救援距离按服务器保存坐标计算（`Party.cs:49,64,74`） | 修复时若仅在某端移动暗影，服务器仍判旧坐标，实际命中可能被拒绝。它是修复必须处理的限制，不是已证实的现行坐标偏差 | **confirmed static constraint** |

`Party.CanRescue` 的 5 单位距离包络用于容纳真实骨钉命中、长骨钉和心跳移动；扩大它不能让玩家走过封门，也不能替代实际命中。

## 测试为何会漏掉

当前测试不是完全没有流程场景：`NativeRescueChecks` 包含 `Crossroads_01`、`Dream_02_Mage_Lord`，危险地形包含 `Fungus1_02`，边界专项还有白宫。缺少的是完整救援路线的验收。

| 测试证据 | 实际覆盖 | 未覆盖 |
| --- | --- | --- |
| `RescueProbe.cs:302` 把救援者移到选定挥刀位置，关闭重力后攻击 | 真实骨钉碰撞、UDP 确认、奖励与防重 | 从战斗中的真实存活位置能否到达暗影 |
| `RescueHazardChecks.cs:45,68,86` 预设危险复位点，断言暗影采用它，再移动救援者到暗影旁 | 尖刺／酸水原生致命碰撞和复位点规则 | 战斗中复位点在封门外、其他楼层或旧战区的情况 |
| `RescueDeathCameraChecks.cs:95,111` 断言采用远处原生暗影标记，再移动救援者 | 死亡镜头能看到落点、能完成救援 | 标记点到实际救援者之间的通路 |
| `RescueEdgeChecks.cs:166,175,230` 选远离入口的室内标记、预设复位点、移动救援者 | 已知良好落点和复活支撑 | 原始入口、封门后复位点、非预设死亡位置 |
| `RescueNativeChecks.cs:55` 主动设置入场位置或零检查点，断言旧优先级 | 原有位置策略的分支执行 | 该策略对流程战斗是否合适 |

这些测试已有的命中、网络、奖励和死亡上下文结果仍有效；不能将它们提升为“流程里队友可到达并救起”的证明。

## 建议的统一规则

1. **区分正式死亡和即时救援。** 保留个人原生死亡上下文，用于主动放弃、团灭和断线返回；即时救援不再无条件优先正式暗影标记或危险复位点。
2. **优先倒地所在区域的安全落点。** 普通伤害优先检查死亡点附近；致命尖刺、酸水或落坑使用本次场景访问、当前战斗区域内最近的真实安全站立记录。缓存需在切房、重试、封场和地形阶段变化时清理或重新验证，不能拿进场前的旧记录兜底。
3. **把“可救”作为完整条件。** 验证支撑、角色与暗影体积、邻近站位／骨钉空间、当前封门和区域归属。直线无遮挡、同房、同屏、直线距离近，都不能单独证明可达；存活队友当前所处的有效区域可作为保守参照。
4. **提供受约束的失败回退。** 原候选全部失效时，可考虑同战区存活队友已验证的安全站位附近；禁止跨房、跨封门或借救援推进剧情。无法找到可靠落点时，应明确显示救援不可用并提供既有个人返回路径，不能静默地永久待救。是否自动返回需要作为玩法选择单独确定，不能在修复位置时擅自改变。
5. **倒地期间处理地形失效。** 当支撑消失、平台迁移或战区改变时重新评估；原点仍有效时保持稳定，避免暗影持续追随队友或成为移动传送入口。
6. **落点变更走可靠同步。** 如果需要倒地后重新放置，服务器记录、双方暗影、倒地本体、复活落点必须一致；沿用当前死亡事件身份，增加明确位置修订与拒绝旧更新的机制。位置调整不能增加死亡数、消耗救援额度、重复奖励或重开一次死亡。当前协议没有直接支持它，不能只改客户端坐标。

“死亡点优先”能够消除一部分错误优先级，但它本身不是全部修复。死亡点在酸水、下层、空中，或对应支撑随后消失时仍需完整处理；也不应通过扩大救援距离来掩盖位置问题。

## 应采用的验收方式

测试先从真实入口进入，在原生触发器或战斗启动后形成实际封门，分别在入口侧、中央、边缘、高处和危险区触发死亡。死亡后，存活角色必须从原本位置通过真实输入移动、跳跃、攻击完成救援；这段验收禁止设置存活角色坐标到暗影旁，禁止 F8、穿墙和清除封门。必要的场景准备、致命伤害注入与实际操控路径分别记录，避免把夹具能力写成产品能力。

| 覆盖类别 | 优先样本 | 核心要求 |
| --- | --- | --- |
| 普通流程 Boss | 螳螂领主、灵魂大师、粪便防御者等真实剧情房 | 原生封场后死亡，暗影留在可救区域，实际走过去挥刀 |
| 梦境 Boss | 失败冠军、失落近亲、灵魂暴君、白色防御者 | 梦钉或原生入口后控制就绪、旧危险复位点不把暗影送回封门外 |
| 非 Boss 关门战 | `Fungus2_05`、竞技场分波战 | 不依赖 BossSceneController 识别战区；波次、封门和个人奖励继续正常 |
| 地形与阶段 | 多层平台、尖刺、酸水、移动／消失平台、破坏地板 | 保留支撑安全与真实可达性，阶段变化后不会留下无法命中的暗影 |
| 网络与生命周期 | 交换主机／客机倒地和房间权威、多人同时倒地、迟入、断连、重试 | 新位置得到统一确认，旧位置／旧死亡事件不能影响当前救援 |
| 规则不变量 | 骨钉命中、救援次数、灵魂奖励、正式死亡上下文 | 位置调整不免费复活、不重复奖励、不改个人进度或存档 |
| 神居对照 | 现有神居样本与辐光平台 | 保留已有行为；不代替流程场景验收 |
