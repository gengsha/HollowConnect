# 危险地形致死后的安全救援

2026-10-16，北京时间。生产修复提交：`25d03c9de070fff4be3f328c4524b40f67e3eba8`。尚未打包、安装或修改版本号；已交付的 0.1.17 包不含本次修复。

用户报告玩家死在尖刺、酸水等原版会复位的地方，队友救起后立即再次死亡。旧版隔离双端测试确认：致命酸水伤害使救援锚点留在酸池，未使用原版安全复位点。

## 原因和最小修正

原生 `HeroController.TakeDamage` 在生命降到零时直接启动 `Die` 并返回，不会执行非致命危险伤害的 `DieFromHazard` / `HazardRespawn`。联机模块截取死亡进入倒地时，原来一律保存当前坐标，因此救援暗影也留在尖刺或酸水里。

`CoopRuntime` 临时记录当前 `TakeDamage` 的危险类型，并在调用结束的 `finally` 清零。倒地时对尖刺 2、酸水 3、深坑 5，复用原版危险复位流程的 `FindGroundPoint(hazardRespawnLocation, true)` 选择安全落点，解除角色父物体并移动救援锚点与角色。生产补丁为 11 行加入、2 行删除，没有新增协议或场景特例。

用户提出的“单人死亡暗影位置”用于表达安全救援的目标。实现使用本次原生危险复位点；`shadePositionX/Y` 是此前正式死亡的个人暗影缓存，不能作为本次安全落点。无需先执行正式死亡来生成新暗影坐标。

普通战斗死亡仍在原地救援。原始死亡上下文先由 `PersonalDeath` 保存，随后才移动救援位置，个人 F6 放弃和全队失败仍可走原生正式死亡。个人暗影、吉欧、一血救起及救人灵魂奖励沿用原逻辑。

- `hazard-rescue-candidate-20261016`：副机酸水救援通过后，下一轮测试使用的 Collider 引用失效，探针空引用；不能计为整组通过。
- `hazard-rescue-reacquire-20261016`：改为逐轮获取 Collider 后，副机救援通过，房主下一轮找不到房内酸水。救援者原站位接近左出口，可能误入相邻房间；当时没有场景追踪，原因未完全证明。探针改站房内一侧，并增加每轮留在原房间的断言，未因此修改生产逻辑。
- `hazard-rescue-native-stand-20261016`：四种救援组合通过，正常退出及停机后严格日志通过，但属于提交前构建，不能代替最终 `25d03c9` 验收。
