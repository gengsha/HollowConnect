# 皮肤动画兼容调查（2026-10-28）

用户提供的 `Lost_Kin_by_teh_ches_noddle.zip` 包含独立的 `Cinematics/StagTunnelRun.webm`。它通过 Custom Knight 替换视频源，不属于普通骑士逐帧动画。此次修改全部位于本模组，未修改或分发皮肤及 Custom Knight。

## 已确认的问题与处理

- 联机动画观察钩子把位与 `&` 当成了帧数取模。原生 tk2d 允许从循环末尾继续播放；6 帧动画从第 6 帧恢复时，原生显示第 0 帧，而原钩子访问第 6 帧并抛出 `IndexOutOfRangeException`。隔离双端已用旧 DLL 复现。现在采用原生相同的 `%`。
- 原生动画事件可以切换动画。观察钩子曾在回调完成后读取新的短动画，并沿用旧动画的事件范围。现在检查动画身份，跳过已失效范围，并拒绝原生本就不处理的方向和越界范围。原生动画、事件及皮肤回调照常执行。
- 原生视频构造函数先调用 `Prepare()`，Custom Knight 随后在同一次构造中将内嵌视频换成外部 URL 并再次 `Prepare()`。本模组在检测到 Custom Knight 时，将原生准备推迟一帧：皮肤已选择 URL 就由皮肤准备；仍用内嵌视频才执行原生准备。提前销毁的播放器不会继续准备。未安装 Custom Knight 时保留即时原生调用。

最后一项消除了确认存在的重复准备时序，但本机未复现用户反馈的进程级闪退，不能把它认定为该闪退的确切根因。动画越界是单独复现的托管异常，也不能等同于已经复现原生进程崩溃。

## 验证方式

使用现有 `game-host` / `game-guest` 隔离副本、内存档及禁止写档的 Smoke 插件；使用原始皮肤、Custom Knight 3.5.0、Satchel 0.9.4。插件下载包按官方 ModLinks 的 SHA-256 核对。未访问或修改私人存档。

真实流程从原生钟道兽目的地菜单出发，运行原生离站、视频播放和到站流程；选择已开放的德特茅斯／十字路车站。逐次要求视频实际解码出帧、正常到站、联机连接保留、房间快照完成、队友可见；交替验证自然播放与原生跳过。测试使用保留图形与视频解码的 Unity batch mode。

覆盖房主单独使用、客机单独使用、双方使用和完全移除皮肤插件的对照；另外运行普通攻击与远端反馈专项。动画边界检查使用独立临时动画实例，不改原生动画资源。

用例选择、旧版失败、最终输入哈希及逐组结果保存在 `.analysis/skin-compat/`，最终结论见该目录的 `final-summary.md`。此前“链在一起”的验收记录保留原哈希，不追认为本次新 DLL 的完整回归。
