# 房间初始与接管快照的旧状态回退

修复提交 `cdc9f339d5eee975c44e185fa729a175b6525233`。用户授权继续处理其他 bug 后，在现有公共接收路径确认并修复此问题；未升版本、打包或安装。

## 原因与改动

`EntitySnapshotHistory.Filter` 已按原始 UDP 序号保护普通实体更新，包括位置、显隐、稀疏 FSM 状态/变量和完整 CombatState。但 `ClientPlayerAlreadyInScene` 与 `HostTransfer.Snapshot` 是包在外层消息里的实体快照，旧实现没有进入这些消息检查内部字段。

因此，较旧的初始/接管快照晚于新实时更新到达时，会覆盖已经收到的新状态；反过来，先到的新房间快照也没有登记字段版本，之后迟到的旧实时更新仍会被接受。可靠重发和序号回绕同样会触发。后果可能是显示对象被重新停用、碰撞体/子物体倒退，以及接管时恢复旧 FSM。

生产改动只有 12 行：沿原始消息的同一序号，递归检查这两种消息中的普通/可靠实体更新，复用既有按字段新旧检查。保持房间身份、权威指派、玩家列表和生成列表；保留较旧消息中未被新包覆盖的稀疏字段与可靠动作。没有修改协议格式、增加重发、全量重建或逐怪补丁。房间级 ID 0 消息及其他 GenericData 类型沿用现有处理，本轮不宣称它们全部获得新旧保护。

## 对照与验证

新增普通回归通过生产 NetClient 分片接收、序号去重、主线程分发与实际编解码，覆盖初始/接管、快照/实时两种新旧关系、原始包/可靠重发、普通序号/回绕共 16 项。旧实现明确 16 项回退失败，其余 147 项通过；修正构建共 163 项通过。它还核对稀疏字段、房间玩家/生成信息和可靠事件没有丢失或重复。最早一次夹具未初始化测试玩家位置，在序列化前失败，保留为无效前置对照；补齐后才得到有效的 16 项失败基线。

隔离 Unity 对照复用原有 CombatState 夹具：真实生产组件产生旧/新字节，经原版包编解码和生产过滤后应用到原生/副本对象，再调用生产接管。四种初始/接管与快照/实时新旧组合，包含回绕、可靠重发和重复原包。旧 HKMP 引擎对照中，双端均明确出现显示/碰撞体/子物体回退；修正构建双端四项及后续接管均通过。此夹具在真实 Mines_11 中运行，并完成普通房间加载和退出；独立夹具没有发送到联机房间，不能说它自然复现了用户的 Mines_11 越界。

旧 Unity 对照指定留档的 `cbc1de3` HKMP.dll，其他模块和测试插件来自本轮测试构建；它用于隔离引擎改动，不能记作某个旧版完整包的验收。所有失败目录保留，最终记录、三个 DLL 哈希、回归日志与停机后严格日志结果见 [机器证据](evidence/scene-snapshot-order-2026-10-15.json)。

最终 `cdc9f33` 构建另完成一组同机双端神居综合回归，真实 UDP/DTLS transport 在加密前按固定种子注入完整应用消息的丢失、乱序与重复。房主进程记录 18,168 条消息，其中丢弃 2,800、乱序 1,727、重复 803；副机进程分别为 5,943、918、567、262。这是测试钩子的应用消息计数，不是网卡 UDP 数据报统计，`nestedResends=0`，不宣称本组覆盖嵌套重发（重发保护另由 16 项矩阵检查）。双方普通双向 F8、格林动态攻击同步与死亡推进、倒地副本等待可转场、神居上下文修复、已接受传送后断开仍完成入场均通过。此组不等于全 Boss 或真实双机 FRP 验收。

两组最终运行均有双方完成、双方网络退出和服务器停止屏障，隔离进程停止后严格复扫日志通过。生产目录、测试输出、两个隔离 Mods 目录及留档的三 DLL 哈希相同；两副本 Smoke 插件已停用。构建成功，仅有原有 `ClientUpdateManager.AddEntityHostFsmData` XML 注释缺少 `isActive` 参数的 CS1573 警告。验收二进制保存在 `.test-results/scene-snapshot-cdc9f33-binaries-20261015`；收尾只改文档，不重建生产 DLL。

测试只使用静音隔离副本、内存角色，拦截三个 SaveGame 重载。合成包顺序验证和同机双端运行都不等于真实双机 FRP 验收，也不能唯一解释旧的 `Thrown` / inactive 飞针、假骑士再次破甲或买地图后互相不可见。本轮不关闭这五项历史未解记录，也不将刚才的战士之梦七位验收改写为本轮构建重跑。

旧 0.1.16 包不包含本轮或此前的传送、复活输入、战士之梦修正。当前仅提交开发源码，`releaseReady=false`。
