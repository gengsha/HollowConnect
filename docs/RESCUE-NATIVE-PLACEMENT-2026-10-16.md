# 救援无敌与原生落位

2026-10-16，北京时间。生产构建提交：`5bc3349`。本轮按用户要求增加救起后的原版受伤无敌和闪烁，并将原生落位机制用于普通战斗死亡的求救暗影。尚未升版本、打包或安装；已交付 0.1.17 不含本轮和上一轮危险地形救援修正。

## 行为

服务器确认本次救援后，受救者恢复一血，并在本机启动 `HeroController.Invulnerable(INVUL_TIME)`。无敌状态、开始闪烁的延迟、原生 `InvulnerablePulse` 和结束后的恢复均由原版处理。使用普通受伤的基础无敌时长，不额外制造受伤、击退或冻结，也不写永久免伤设置。原版仍按自己的规则处理无敌期间的尖刺、酸水等危险伤害。

队友显示对象没有 `HeroController`，由短生命周期 `RescueFlash` 复制本机原生脉冲的颜色和周期，运行原生 `InvulnerablePulse`。结束或对象停用时移除该组件并还原显示对象自身原有颜色；只有受救者本机的原生协程负责伤害免疫。重复或过期的救援确认沿用既有死亡序号筛选，不重开无敌或闪烁。

求救位置按当前死亡上下文选择：

1. 尖刺、酸水、深坑致死优先使用本房间原生 `hazardRespawnLocation`。
2. 普通场景的其他死亡优先寻找本房间最近的原生 `Shade Marker`，向下使用原生 `FindGroundPoint` 取得支撑，再复用现有传送落点检查，给骑士完整碰撞体留出空间。暗影的 `Spawn Offset` 用于漂浮美术，不直接当作活人站立位置。
3. 梦境、神居、白宫，以及没有可用标记或标记不安全的场景，使用本房间原生危险复位点；没有有效复位点时尝试死亡位置下方的支撑。两者均不可用则保留原位置，不凭空生成坐标或擅自跨房。

原生扩展地面查询在无命中时会报错并返回接近 `(0,0)` 的结果，因此调用前先确认同房间地形命中。完整身体的碰撞、危险区和净空检查沿用 `TryWarpLanding`；没有新增独立的落点搜索框架。

`PersonalDeath` 在移动求救位置之前保存原始死亡上下文。F6 和全队失败仍运行原版正式死亡，包括个人长椅、梦境返回、吉欧和个人暗影；竞技场、最终 Boss 等把正式暗影放在其他房间的分支仍由原版处理，救援位置只在当前房间选择。

## 原生依据

只读目录：`E:/SteamLibrary/steamapps/common/Hollow Knight`。原生 `Assembly-CSharp.dll` SHA-256 为 `5944411BD93830369390A4B51766EE68C4AB26195B299E25A07B5E7D0E00086D`，`PlayMaker.dll` 为 `0EF0E7829D125E1F632C8A189260EC6C6882630BE6932C8C7AE032EFBC53469A`。原生代码与已有死亡 FSM 只读导出保留在 `.test-results`。

- `HeroController.StartRecoil` 启动 `Invulnerable`；后者设置临时无敌、启动原生脉冲、等待时长后关闭脉冲并恢复状态。
- `Hero Death/Hero Death Anim` 的 `Set Shade` 使用 `FindClosest` / `Shade Marker` 取得普通暗影位置，`Shade Marker Check` 处理无标记情况。
- 原生死亡 FSM 为梦境、白宫、神居分支使用梦境死亡动画；竞技场和最终 Boss 正式暗影有跨房位置例外。
- `PositionShadeMarkerPerDoor` 会按本次入口移动标记；运行时读取实际标记位置，无需维护逐场景坐标表。

## 边界
