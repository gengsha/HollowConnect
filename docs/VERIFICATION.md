## 0.1.5 隐性缺陷审计

- 以 0.1.4 为基线增加失败复现，原 67 项通过，新 3 项失败：断线后已排到 Unity 主线程的旧 packet 回调仍执行；被拒连接保留 DTLS transport；接收中的连接数据没有核对 ChunkId，未来块的片能混入当前块。[失败基线](evidence/audit-baseline-0.1.4.txt)。0.1.5 的普通更新、连接数据和两种 addon 回调统一按会话代数隔离；拒绝执行完整资源清理；分块核对编号、数量和长度，并在触发完成回调之前提交状态。
- DTLS 取消时，旧握手仍使用可能被清空的共享字段，甚至能在取消后发布 transport。每次尝试使用独立 peer，资源通过局部引用操作，已取消 peer 不能延迟启动；接收和超时也绑定各自会话。实际对一个已绑定但无响应的 UDP 端点执行 40 次快速连接 / 取消，再连接真实 DTLS 服务，拒绝后重连，触发旧超时和旧失败，新的连接仍有效。握手失败通知只在主线程执行，不触发后台游戏断线事件。
- 在完整双客户端中，第二轮全队 Release 后向两端重放同轮 Wipe，旧实现再次进入 Resetting 且不会再收到 Release，两端均失败：[房主基线](evidence/wipe-replay-baseline-host-0.1.4.log)、[客机基线](evidence/wipe-replay-baseline-guest-0.1.4.log)。修复后记录已释放轮次，同轮重放不切房、不重新锁角色；尚未释放的迟加入者仍允许进入当前轮的屏障。
