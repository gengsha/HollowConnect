# 灵魂战士召唤小怪静滞（2026-10-23）

用户反馈五门灵魂战士的小怪悬在空中、不移动且无法击杀，并怀疑普通流程存在同类问题。隔离双端确认是原生召唤器与小怪池的所有权缺口。

## 原因与实现

| 原生位置 | 已确认行为 | 修复 |
| --- | --- | --- |
| 五门 `GG_Mage_Knight_V`，原生序列索引 8（包含中场） | `Balloon Spawner/Battle Control` 每 4 秒从 `Balloons` 随机选择并激活小怪；上层未登记，两端各自执行，副本还可能挂回原生池并被本地随机激活。 | 以现有 `CombatSpawner` 配对 `Balloon Spawner → Balloons → Folly`，让一端控制生成器及原生小怪池。 |
| 普通流程 `Ruins1_31b` | `Battle Scene v2/Battle Control` 的 `Battling → Spawn` 每 4–5 秒从其 `Balloons` 池激活小怪；该控制器还负责各玩家的入口触发、战斗计数、门和镜头。 | 只配对 `Battle Scene v2/Balloons → Folly`，保留本地战斗控制器。副本池和原生池分开，非权威端原生池保持停用。 |

`Mage Balloon Spawner` 本身是带 `HealthManager` 的 Folly 小怪，初始 13 血，不能因为名字带 Spawner 就排除。既有独立 Folly 登记保留。新增条目均使用显式父子关系；Boss 支援池及其子实体在关闭共享永久进度时仍然同步。

本轮生产修改仅在 `src/HKMP/Resource/entity-registry.json` 增加两组条目，没有改网络数据布局或通用实体生命周期。修复复用既有配对、状态、位置、碰撞、健康、迟入及接管机制。

旧生产基线 `folly-20261023-baseline` 保留了静滞副本证据，还在严格日志中捕获 `ChaseObjectV2.DoChase` 空引用。早期诊断的 `FINAL PASS diagnostic` 只表示记录完成，不作为移动或击杀验收。

## 边界与额外发现

本机既有两份隔离游戏通过真实 UDP 运行，使用禁止存盘的内存角色。没有测试完整五门通关、完整人工战斗、跨机器网络、竞技场或普通 Folly 的所有房间。未升版、打包、安装或修改个人存档。

保留了一项独立产品错误：Boss 死亡后结算尚在途中，测试立即断开连接，`CoopServerAddon.Tick` 会尝试向已离线参与者发送 `BossSettlementReady` 并抛异常。该次检查判为失败，未忽略日志；替代清理用例验证正常结算完成后退出。此次小怪登记修复不解决“结算途中立即断线”竞态。

另一项失败属于夹具：接管后重复检查小怪池时，访问了先前已被骨钉击杀并销毁的副本。修正只排除已由两端击杀检查确认死亡的 ID；未死亡小怪仍要求两份对象和正确父子关系。更改范围及有效旧结果的复用理由均记录在 `failure-notes.md`。

关闭共享的初次检查也暴露了夹具竞态：两端均已观察到两只召唤物，一端已经开始移动角色，另一端仍要求数量恰好保持至少两只。补充逐对象诊断确认所有现存小怪的归属正确；修正为双方先完成池检查再移动，并要求至少一个现存对象、每个对象都归属正确。此前“两端各自实际看到至少两只召唤物”的断言保留，旧失败和诊断日志也保留。
