# 共享鹿角站刷新与科尼法地图可见性

用户在 0.1.14 双机正常流程中推进至真菌荒地并击败大黄蜂，报告两个实际问题。共享永久进度开启；地图消失场景中双方都购买了科尼法地图，之后互相看不见，队友定位仍实时更新，跨场景不恢复，重开联机房间暂时恢复。鹿角站进度会共享，但接收者当前场景仍允许付费，实际会扣钱，切换场景才刷新。

## 已修：鹿角站重复付费

`CoopRuntime.ApplyProgress` 原来只更新 PlayerData，没有调用 HKMP 已有的 `SaveChanges.ApplyPlayerDataSaveChange`。存档字段为真不等于当前 Stag Bell FSM 已退出购买流程。

隔离双客户端失败基线 `progress-baseline-20261015-a`：房主通过原生购买提示支付 50 吉欧并开启遗忘十字路站；副机在购买提示中收到 `openedCrossroads=true` 后，仍停在 Send Text / Ready for Input，拥有 500 吉欧。副机确认后再扣 50 吉欧，探针明确写入失败。保留原日志和旧生产 DLL 哈希，失败不计入验收。

修复提交 `debdef9`：增加现有 SaveChanges 实例，在共享进度应用后调用当前场景刷新。复用原来的开站动画和对话关闭/控制恢复动作；进度 ledger 原来的 Merge 去重继续阻止重复应用。不增加逐帧机关扫描、强制全房 FSM 初始化、重试或兜底 catch，不扩大共享字段白名单。

0.1.15 当前哈希专项覆盖未交互接收、接收者正在购买提示、交换购买者、重复进度 offer；断言仅购买者扣 50、接收者不扣钱、同一房间进入 Opened、对话 Idle、原生控制恢复、队友角色可见和快照提交。验证只包含遗忘十字路鹿角站，其他站点与双方在共享消息到达前同时付费的竞争尚未单独验证。

## 待定位：双人买地图后持续不可见

私人客户端日志确认实际载入 0.1.14。在买地图附近的 Crossroads_33 / visit 9、Crossroads_08 / visit 10、Crossroads_30 / visit 11 只有场景准备，没有已提交快照；重连后 visit 12 恢复。没有发现 HKMP ERROR 或含 Hkmp/HollowConnect 的异常栈。这提示场景入场链路值得调查，但缺少朋友一端的服务器日志，不能认定地图购买、共享进度或角色渲染就是根因。

隔离专项实际走科尼法的 Take Control 交互入口、原生对话和 Yes/No 支付事件，保留真正的 TakeGeo、地图字段更新、SetupMap 和首次地图提示；随后关闭对话并跨 Crossroads_08、Crossroads_30。测试包括双方购买地图，检查角色激活、Renderer、forceRenderingOff、透明度、网格、房间快照及个人地图/吉欧。没有复现用户报告。程序化进入交互和推进对话不等于完整人工输入，且同机 localhost 测试不等于实际双机 FRP 条件。

`bb8f15b` 只增加正常日志中的入场发布、过期快照和入场拒绝 scope，没有更改同步逻辑。它是诊断改进，不是这个问题的修复。新版本保留该未定位问题；复现时需要双方 ModLog.txt / Player.log，私人原日志没有打包。

## 验证与保留记录

最终三个生产 DLL、两组专项终态和日志哈希见 [0.1.15 运行记录](evidence/runtime-room-0.1.15.json)。自动回归 143 项通过，严格日志检查 14 项通过；每组专项正常退出网络后复扫日志。旧版神居/死亡六组不记为本版验收，完整矩阵仍未完成。

最终哈希的第三候选组 `version-015-progress-prompt-host-20261015` 不计为通过：副机的 Crossroads_33 输入就绪断言超时，日志确认它在入场后自行进入 Crossroads_09；双方随后均发布/提交侧边房间快照。探针没有完成目标房间的地图购买，该运行保持拒绝并保存当前 DLL 哈希。此样本不能证明用户的地图不可见已复现，也不能把它伪记为购买通过。

诊断中间运行也保留：`progress-inspect-20261015-a` 使用不存在的入场门而超时；`progress-map-20261015-a` 在功能断言后被直接停止房主，产生 ConnectionReset，严格门槛拒绝；`progress-map-20261015-b` 的测试角色在入场控制尚未完全恢复时移动至下一房间，未完成对话；`progress-map-20261015-c` 对初始坐椅角色使用了不适用的输入就绪要求而超时。后续夹具等待原生场景过渡完全结束，使用已有 ProbeShutdown 正常关闭，再写终态。没有删除这些失败、放宽生产断言或通过新增 catch 掩盖错误。
