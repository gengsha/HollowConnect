# 黑波前房间：队友关门后 Boss 未启动

共享永久进度开启、无人曾击杀该 Boss 时，`Ruins1_31b` 仍可出现队友进入中央后关门，而灵魂战士没有启动。原因是原生 `Battle Control` 和门属于各玩家自己的场景；控制敌人的玩家停在右侧时，其控制器仍在 `Detect`，Boss 停在 `Sleep`。0.1.30 与修复前 0.1.38 都有此问题，复现证据在 `.analysis/shade-soul-entry-20261025/`。

修复将真实原生 `BATTLE START` 动作转换为可靠的入口请求，由负责敌人的一端执行原生入口事件。Boss 激活、召唤计时、敌人计数和结束流程继续使用原生控制器。复用既有 `EncounterSummon` 的权威登记、请求重发、一次性回执和场景/访问/轮次校验，没有新增网络包字段或修改通用实体生命周期。

只有满足以下结构的本地战斗才启用：已登记 Boss 原生 FSM 接受 `BATTLE START`，同场景恰有一个带真实触发碰撞体的本地 `Battle Control`，且该触发事件的目标状态立即广播 `BATTLE START`。无法确认结构时保持原流程。不会把任意场景事件或普通机关转换为战斗请求。

远端触发时，先暂缓原生入口中的关门和镜头锁定动作；当负责敌人的玩家自己进入真实触发区后再执行这些动作。这样敌人无需等待该玩家走到中央，门和镜头仍跟随自己的入场。若战斗已结束则取消待执行的关门，避免战后重新锁门。原生初始化会稍后填充镜头变量，因此在实际入口时识别动作目标。

实现位于 `src/HKMP/Game/Client/Entity/LocalBattleStart.cs`，由 `Entity.cs` 绑定到符合结构的 Boss，`LocalBattleCompletion.cs` 观察原生入口动作，`EncounterSummonComponent.cs` 复用现有可靠请求。没有修改私人存档、安装目录或历史发布 ZIP。

验证遵照用户“时间紧，只做必要验证”的范围：8 项相关核心检查和 3 组同机双端实机；未扩展完整房间矩阵或所有 Boss 套件。逐组生产哈希、诊断插件哈希、选项、状态、失败和日志位于 `.analysis/shade-soul-entry-fix-20261025/`。第一版修复预检查出的镜头绑定问题已保留，不作为最终证据。

最终 8/8 项核心检查、3/3 组双端实机及严格日志通过，全部匹配最终生产哈希；结果见同目录 `evidence.json` 及 `docs/evidence/battle-entry-fix-2026-10-25.json`。延迟入场组检查 Boss 与 Folly 在权威玩家尚未进入中央时活动、该玩家门和镜头保持本地、随后进入时正常关门，以及通过原生健康伤害边界结束 Boss 后双方开门和真实结算。该结束检查不等于完整人工战斗。第三组检查双方正常进入中央的原生开战。实际使用既有两个隔离游戏副本，未验证三客户端或异机网络。

本地构建位于 `src/HollowConnect/bin/Release/net472/`。修复未改显示版本号，历史 0.1.38 发布 ZIP 仍是修复前文件；本轮结果仅适用于修复目录记录的新哈希。没有打包或安装。
