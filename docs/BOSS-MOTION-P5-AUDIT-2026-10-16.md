## 存档边界

通过 `ILocalSettings<DeathStatistics>`，由原有 Modding API 的保存时机写入 `user{slot}.modded.json` 的 HollowConnect 字段，不修改原生存档格式、PlayerData 类型或个人存档。读档前及新建存档时清空当前内存榜，再加载该槽位的数据，避免旧存档没有模组字段时串榜。没有新增每次倒地强制 SaveGame 的磁盘写入；正常坐椅/退出保存时一起落盘。卸载 HollowConnect 后原版无需读取这部分数据，原生存档可继续使用。

按名字识别记录：同名合并，改名另列；复制/分支存档重新合并取最大值，不把两个分支相加。只累计启用联机后的实际死亡，旧版没有记录的历史死亡无法补算。

实际 Unity 中调用 Modding API 的 OnSaveLocalSettings / OnLoadLocalSettings，经专项目录内 JSON 文件读回。测试文件只含测试名；未调用个人存档写入，原生 SaveGame 的全部三个重载继续被隔离插件拦截。此验证不冒充真实玩家存档的卸载重载实测。

## 选择性验证

14 项直接相关自动检查通过，选择理由是位置采样、死亡累计/重复历史、消息编码及受影响救援/检查点公共边界；没有重跑无关的旧 100 项矩阵。选择文件 `.test-results/motion-deaths-persistent-selected-20261016.txt`，最终结果 `.test-results/motion-deaths-persistent-hc11-selected-20261016.log`。

同机、双客户端、静音、内存角色运行，逐组原始哈希见 [机器记录](evidence/boss-motion-p5-deaths-2026-10-16.json)：

- `p5-watchers-018-baseline-20261016`：旧交付三 DLL；直接进入原生第五行程索引 31，六个守望者实际 HealthManager 致死，双方正常到乌姆。这是未复现基线，不是修复证明。
- `p5-motion-persistent-rescue-20261016`：当前中间构建；格林战双方各倒地并经实际服务器请求救起一次，正常结算后经温泉、乌恩原生出口、守望者到乌姆。存档历史合并和模组 JSON 往返通过。
- `p5-motion-persistent-final-20261016`：加入逐帧运动与子物体接管检查、明确延后另一人入格林，再走同一段原生行程；双方到乌姆后断开、停止旧房、重新开房连接，累计 8/5 和离线队友 2 均保留，没有重复相加。正常网络退出、停机后严格日志通过。

- `replica-grimm-motion-hc11-20261016`：复用原生格林运动探针，实际 72 次气球火球发射的力/协程保留、72 次位移和 15 个移动火蝠通过，迟入副本跟随及无自主物理叠加检查通过；正常网络退出、停机后严格日志通过。未运行完整接管矩阵。

P5 探针直接设置第五行程的格林索引 28 开始，没有从五门入口重打前 28 场；致死使用原生 HealthManager，未强设 Boss FSM。救援走真实 UDP 请求，但没有重测骨钉碰撞。两次前置救援专项都没有复现用户的提前返回，不能据此排除完整五门、真实多机或其他中间场景的问题。

保留失败证据：`p5-motion-deaths-current-20261016` 是测试把只写 Packet 当成可读包导致的 Decode 空缓冲错误，已改为编码后构建接收包，不算生产 bug 修复；`motion-deaths-persistent-selected-20261016.log` 中一次失败是非 Unity 单元程序直接 new Mod 触发 Unity ECall，改为纯数据单元检查，并把实际 API 检查放入游戏进程。失败原文未删除，不转记通过。
