# 对减少联机故障建议的处理

先改善可追溯性、失败判定和对象生命周期，再补验收，这个顺序合理。网络路径不是双方 Boss 状态分叉的修复前提。本轮冻结新增玩法。

1. **Git：已建立本地仓库。** 当前工作状态作为基线；日志门槛和 UDP 关闭修复分别提交。旧源码 ZIP 可以比较，但不能据此声称已经恢复过去全部版本的可靠开发历史。没有推送到远端。
2. **日志判失败：已统一。** 所有实机探针捕获模组异常、HKMP ERROR 和 `Spawn expired`；汇总扫描双方全部日志，包括独立引擎文件及原生崩溃标记。完成后的失败也有效。门槛有 14 项自检，并确实拦出了此前重开房检查中的 UDP 关闭异常。逐行异常扫描保留堆栈边界，避免超长日志拖慢汇总。
3. **对象退役和初始化：按语义修。** 房间卸载先移除整张表，再释放对象；动态对象结束后退出活跃表；静态 Boss 的网络死亡记录仍需保留，以免后来者把死 Boss 重新生成。0.1.7 到 0.1.9 的标志赋值提前属实，但该标志也放行入场事件，不能盲目回退。当前入口拒绝失效 Unity 对象，初始化 ERROR 会直接使测试失败。进一步实机确认并修复初始化清空脱离层级的攻击引用、重连激活重启已运行 FSM、接管缺少刚体初始速度三项根因；两种先入顺序的六轮投针重连专项通过，最终哈希整套另验。
   后续严格重连又查明静态飞针按可变层级重算身份、本地暂停清零刚体速度，以及副本复制运行中 iTween 却取不到原物体私有参数三项根因。每项保留失败基线、定向前后对照，并分别提交；未通过降低日志门槛或新增 catch 放行。
4. **冻结功能：已执行。** 当前仅修公共同步、清理、关闭与已发现的验收缺口。自动回归或少量房间通过，不能代替逐 Boss、全部招式、流程奖励和真实双机验收。
5. **更新成本：保持覆盖安装，避免无必要的协议升级。** 一键安装自动发现各盘 Steam 库，或接受任意手选目录；无需先卸载或重配隧道。正在使用的 DLL 仍需退出游戏后更新。此次子物体父级快照改变了协议，0.1.12 升至 0.1.13 必须双方一起更新；随后 UDP 关闭和原生状态/刚体恢复修复复用 hc10 消息，没有再次升级协议号。尚未实现运行中热更新或跨版本兼容，不能承诺玩家只需更新一端。

EasyTier / Tailscale / 端口转发可以作为联机方式选择。它们不会修复旧实体清理抛错、场景登记中断、重复监听器或丢失原生子物体引用。保留樱花 FRP 的 UDP 配置，先完成模组验收，再验证实际两台机器的连接。

当前生产构建 `6ddf5b3` 的 12 组静音双客户端专项全部通过，双方三项 DLL 哈希、终态及严格日志一致；109 项自动回归、13 项安装器检查通过。三组真实镜头判定对照也成立。正式发布状态以 `docs/evidence/runtime-room-0.1.13.json` 为准；历史入场镜头冻结仍未解决，成功重跑不会抹去失败记录。用户明确要求先打包试玩后，提供独立标记的试玩包，保留未解决问题和正式发布阻塞，不重建已验收的生产 DLL。
