# 0.1.9 晚入场与重连修复

版本：HollowConnect 0.1.9 / HKMP 3.0.0-hc6。双方同时更新完整包；一键安装支持自动查找 Steam 库及手选游戏目录，FRP 使用原来的 UDP 设置。

## 已复现的原因

旧版本先应用等待中的实时变化，随后应用更早捕获的初始房间快照。Boss 和摄像机锁区在入场期间从关闭变为开启时，较旧的关闭值最后覆盖新状态；激活值只在变化时发送，之后不会自动恢复。停用的 Boss 原始物体仍能接收远端伤害，所以“看不见、挥空气却能打中、击杀后仍能转场”可以同时出现。

在两个隔离的真实 Unity 客户端上延后实际初始快照三秒，并让先入场端在快照捕获后启用 Boss / CameraLockArea，0.1.8 的后来入场端留下 Boss 与镜头锁区关闭，而先入端正常。人工延迟和物体启停只在测试插件中发生，发行代码没有这些故障注入。

另复现了已加载房间直接连接无法初始化、快照延迟期间队友移动后停下仍显示旧位置，以及先入场者在初始快照到达前离房导致接管失败。这些是通用入场时序缺陷，修复没有写死大黄蜂或某一 Boss。

断线复测还确认了服务端提前删玩家资料的问题：断线处理随后找不到离房者，跳过模拟权移交和空房缓存清理。全部玩家断开后，房间仍留着上一轮的实体快照。这会污染下次重新挑战；现保留离房者资料直到完成移交 / 空房清理，再移除玩家。

## 实现与复测

| 问题 | 处理 | 双人复测 |
|---|---|---|
| 晚入场 Boss 消失、镜头偏移 | 初始快照先提交，后应用实时变化；晚加载实体同样遵守顺序；重复初始实体快照不再覆盖。 | 在队友开打后延迟入房，双方都能看见同一 Boss，镜头锁定区域正确。 |
| 重进后独立战斗或没有队友 | 已就位角色补发遗漏入口；同房直接连接显式注册当前场景；每个场景 handle 只发布一次。 | 退出重连后重复挑战，双方人物、Boss 身份、血量一致。 |
| 上一房延迟消息移除当前队友 | 玩家消息校验场景、重试及双方访问编号；重复 Connect 保留现有角色资料。 | 连续转场、往返同房和晚入场后队友持续可见。 |
| 入场快照中队友停在旧位置 | 合并进房前的最新位置、朝向、最后动画帧，角色创建后回填；不补放历史攻击特效。 | 队友在另一端加载期间移动后停下，后来者看到当前位置。 |
| 初始快照未到时提前接管失败 | 权威移交先完成副本初始化并提交状态，再恢复模拟；旧初始快照不能撤销已完成的移交。 | 先入场者在后来者加载期间离房，留下者继续模拟敌人。 |
| 等待中的房间上下文无法应用 | ID 0 房间消息进入独立处理路径，不等待不存在的实体；协商期间缓存的结算 / 布局 / 行程正常重放。 | 连战延迟结算后正确进入下一 Boss 房，未出现重复推进。 |
| 快照排队后混入更新状态 | 在服务端场景锁内深拷贝组件、FSM 和缩放数据。 | 连续进出房与接管期间无共享字典修改导致的快照失效。 |
| 断线或重进后沿用上一轮房间状态 | 断线处理先完成离房、移交与空房缓存清理，再删除玩家资料，整个过程在场景锁内执行。 | 权威断线后留下者继续战斗；全员断开重进后创建新 Boss。 |
| 苍蝇之王召唤物无法重建 | 读取 EnemySpawner 的实际 enemyPrefab；副本 Awake 不额外生成本地敌人，不重放相对移动。 | 两端都能看到召唤的小苍蝇，换先入顺序后仍一致。 |

实际通过的检查、最终 DLL 哈希和验证范围见 [验证记录](VERIFICATION.md)。相机检查覆盖同步锁区、非冻结模式和真实连战转场；批处理测试没有逐帧截图验收画面构图。它也不能证明真实 FRP 两台机器上所有 Boss 招式都已通过。

复测建议先交换先入房者，各重复两轮一门；特别记录苍蝇之王、假骑士和大黄蜂的入场、血量、队友显示与击杀转场。发生异常时保留双方 ModLog.txt / Player.log，记录房间、先入者和是否在重连后出现。
