# 同步资源本地重复领取的碎片界面收尾修复（2026-10-20）

修复[版本对照中已复现的商店卡住](SHOP-SHARD-STALL-AUDIT-2026-10-20.md)：容器碎片已由共享奖励合成、余数为零后，本地再买同一来源，原版 UI 的 `Fleur` 没有 0 分支，玩家一直失去控制。面具碎片和真实世界拾取使用同类 UI 交接，因此一并处理。

## 修改

仅修改 `ResourceShareService.EnterState` 的碎片 UI 入口。在 `Init` 已解析 Hero 等引用、即将进入 `Darken` 时，核对本次 `inFlight` 的 `Duplicate`：

- 首次领取保持原版完整显示、碎片累计及合成；不能用领取后已经为真的来源回执误判首次领取。
- 重复来源通过原生 `Fsm.SetState` 正式切到 `Hero Anim End`，由原版 `Destroy Self` 恢复重力、无敌标记、动画控制、暂停和输入，并销毁 UI。跳过依赖碎片计数的展示，不虚增临时碎片，不手动提前放开角色控制。
- 仍等待原版流程实际结束，再提交本地场景领取标记和移除 `inFlight`。适配适用于两类碎片 UI，通过已识别的商店、世界来源或 NPC 奖励映射进入。
- 世界来源继续取并集，重复购买不扣钱、不增加资源；远端碎片仍直接结算并显示左下角原版提示，个人骨钉和矿石消费规则保持原有实现。

本次修改前的完整资源服务保存在 `.analysis/shop-shard-fix-20261020/ResourceShareService.cs`。五门修复涉及的四份生产源码哈希与此前记录逐项一致。本次仍为开发中的 0.1.27，未重新打包或安装。
