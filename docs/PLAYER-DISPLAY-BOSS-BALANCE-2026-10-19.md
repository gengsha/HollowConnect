# 队友显示、皮肤选择与 Boss 难度（2026-10-19）

本轮按用户范围实施四项：修复 HKMP 皮肤编号不能用鼠标减少、配置队友透明度、统一名字与方位颜色、配置按人数增加 Boss 等效血量。前三项只验证可用性，Boss 难度执行专项风险检查。本轮不升版、不打包。

后续配置调整：Boss 人数难度默认关闭，房主在配置中显式设置 `BossHealthScaling: true` 才开启。下面 JSON 是开启示例；已有配置保存的 `true` 会保留。此项默认值调整不改变下文历史受测 DLL 或测试结果。

## 配置与行为

2026-10-20 源码已补全三个模组菜单入口，不再要求手工编辑 JSON；名字配色新增本机开关。默认透明度关闭、名字配色开启、Boss 难度关闭。详见 [菜单设置修订](DISPLAY-MENU-2026-10-20.md)；本文后面的验收和哈希仍属于原历史构建。

关闭游戏后编辑 `%USERPROFILE%\AppData\LocalLow\Team Cherry\Hollow Knight\CoopMod.GlobalSettings.json`，保留文件其他设置：

```json
{
  "OtherPlayerOpacity": 0.5,
  "BossHealthScaling": true,
  "BossExtraHealthPerPlayer": 0.6,
  "BossExtraHealthDecay": 0.6
}
```

- `OtherPlayerOpacity`：本机队友身体、刀光、法术、冲刺、羽毛和粒子等透明度，范围 0～1，默认 1。覆盖 HKMP 远端特效的独立实例与池化生成入口，包括离开角色层级的火球。缓存本对象的渲染组件，按原生 alpha 乘一次；回收恢复原色，避免逐帧累乘或修改共享材质。名字单独维持可读配色。
- 名字按 HKMP 玩家 ID 复用地图/方位的 HSV 颜色函数，自己保持白色；创建、队伍更新和角色池复用都使用同一规则。
- 皮肤菜单在真实鼠标点击入口按横向选项的本地坐标区分左右，绕过原生箭头命中失败后默认增加的路径。保留原生键盘方向和设置应用回调。
- 难度由房主开服时取值，通过现有可靠 Welcome 字段下发；访客自己的难度配置不会覆盖房主。无需增加封包字段。

人数为同房间的本机玩家加队友；暗影、原生过场或临时失去操作的玩家继续计数，正式回椅中的玩家不计。进出房间影响后续伤害，不修改当前 HP，不凭空加血。

倍率为 `1 + extra + extra×decay + extra×decay² + …`，每多一个玩家多一项，单人为 1。默认依次是 100%、160%、196%、217.6%，人数很多时趋近 250%。`extra` 限定 0～4，`decay` 限定 0～1，总倍率最多 10，非有限配置安全退回原值。

为保留假骑士、灵魂大师、辐光等原生阶段 HP 与脚本阈值，采用 **Boss 最终有效伤害 ÷ 倍率**，不重写最大血量、阶段血量或玩家骨钉/法术属性。普通敌人不应用此倍率。已注册 Boss 和假骑士/躁郁毛里克的独立受伤部位使用同一入口。

缩放位于 HealthManager 原生攻击倍率、单次伤害覆写之后；玩家的 ExtraDamageable 持续伤害同样折算。原生 Generic 脚本伤害、9999 处决和直接 ApplyExtraDamage 保持原值，避免拖住过场。只有当前权威的原生对象结算倍率，双方继续使用已有绝对 HP 快照；销毁实体时移除伤害登记。小额伤害累计小数余量，避免 1 点伤害被一直舍弃。余量不增加网络字段，切换权威或恢复单人时最多存在不足 1 点原生 HP 的舍入差。

## 追加：Boss 真正死亡后伤害是否正常

玩家的骨钉、法术等级和攻击属性没有被降低，也没有需要在胜利事件里恢复的全局攻击倍率。每次原生扣血时按目标判定，只有登记的存活 Boss 才折算。普通怪即使与 Boss 在同一房间、双人难度仍启用，也必须按原值扣血。

为回答这一问题，追加 `rescue` 探针的显式 `HOLLOWCONNECT_POST_BOSS_DAMAGE_CHECK=1`，配合 `HOLLOWCONNECT_LOCAL_BATTLE_CHECK=mother`。分别交换房主／访客先入并负责原生战斗：真实挥刀唤醒格鲁兹之母，确认双人 Boss 的骨钉、法术与玩家持续伤害按 160% 等效血量折算，再经原生终结伤害击杀，等待尸体实际放出七只小怪。小怪通过原生 TakeDamage/ExtraDamageable 入口接受固定非致命伤害，验证骨钉 1、法术 1×2、持续伤害 1 依次全额扣血，另一端 HP 收敛；这些精确伤害检查没有模拟三种攻击的完整碰撞过程。双方全过程的骨钉伤害、升级数和三种法术等级不变，战斗结算后开门，再正常离房、断线。

诊断组 `post-boss-damage-host-20261019-a/b` 中，小怪伤害已正常，但发现原生 Boss 销毁后仍有一条登记跨房残留。因此在房间实体统一清理处追加 `BossDamageScaling.Clear()`；保留原有单实体移除与断线卸载，避免残留登记跟随到下一次房间访问。诊断失败证据保留，不计入通过结果。

修复后两组死亡专项通过：`post-boss-damage-host-20261019-c`（房主／访客 42 / 31 项断言）、`post-boss-damage-guest-20261019-a`（30 / 43）。两端均验证离房登记为零、断线 Boss 倍率回到 1，隔离进程停止后严格日志检查通过。核心原 4 项在清理修复后再次通过。

同一批新 DLL 的假骑士回归也通过：`boss-balance-cleanup-20261019-a`（42 / 44）、`boss-balance-cleanup-late-20261019-a`（36 / 45），两组退出后严格日志检查均通过。覆盖正常／迟入、原生破甲、头部受伤与接管、后续阶段 AI、旧权威回房与再伤害，以及前三项显示／皮肤可用性检查。接管时两组仍为 Opened 暴露阶段，没有覆盖暴露超时后重新破甲的分支。各组完整哈希与结果见 evidence JSON。
