# 0.1.7 集中修复与审计对照

对应用户提供的 `boss-net-audit-summary.md` 和五份 `slice-*.md`。五张 Findings 表共 49 条，编号按各表出现顺序排列。汇总中的重复项归入相同机制处理。本轮修改的是通用实体、生命周期、伤害和神居上下文机制；逐 Boss 实战验收仍待后续进行。

版本为 HollowConnect 0.1.7 / HKMP 3.0.0-hc4。双方必须一起更新，与 hc3 及更早版本不兼容。

## 血量、死亡与阶段：slice 1

| 编号 | 发现 | 本轮处理与验证边界 |
|---|---|---|
| S1-01 | `hasSpecialDeath` 不发普通死亡 | 独立可靠 `SpecialDeath` 镜像原生 ZERO HP 阶段事件，保留特殊死亡语义。纠正报告的部分前提：原生特殊死亡本来也不执行普通掉落/尸块分支，不能强制把它改成终结死亡。 |
| S1-02 | 三处死亡门闩阻止阶段复位 | 新增带版本号的明确 `HealthReset`，只有更新的复位事件能重开墓碑；普通旧 HP 包不能复活死敌。池化重生另用全新实体 ID。原生确实销毁的对象由生成路径重建，不用 HP 猜测复活。 |
| S1-03 | 易伤、眩晕、战斗引用等字段缺失 | 补上 `hasSpecialDeath/deathReset/damageOverride/preventInvincibleEffect/notifiedBattleScene`，以及本机眩晕 FSM 和战斗对象引用，接管前恢复。 |
| S1-04 | 假骑士三段护甲及头部阶段 | 使用 S1-01～03、独立子体身份和 FSM 引用快照共同处理；仍需逐阶段验证假骑士、失败冠军及神居变体。没有把此前第一阶段的通过记录扩大为全阶段通过。 |
| S1-05 | 击杀后权威离房，剩余端不能完成 | 休眠原生对象收到死亡通知；房间级完成记录独立于单只怪物。新权威可按原生明确 `isDead` 检查继续收尾，禁止用零血代替完成。 |
| S1-06 | 文档声称 HP 每秒才同步 | 修正文档：数值变化即发送；无变化时每秒保活。该发送策略此前已存在。 |
| S1-07 | 未具名注册的危险弹体 | 为已注册来源实际生成、带 `DamageHero` 的动态对象提供通用危险物类型，同步位置/旋转/深度、激活与碰撞，停用副本的原生自主控制。纯尸块和装饰不作为战斗实体推测注册。 |
| S1-08 | `ApplyExtraDamage` 与伤害覆盖缺失 | 权威额外伤害事件镜像到副本，HP 仍用绝对快照，不重复减血；补上 `damageOverride`。一次性阶段/额外伤害各用独立去重版本，避免较新 HP 抢先到达后吞掉阶段事件。 |

## 本轮回归额外发现

- 场景对象引用原先逐个扫描全部已加载对象并重建路径，弹幕密集时会使副本单帧耗时非常长。改为按场景、同名序号和层级直接查找，并转义路径分隔符。
- 池化实体频繁注册/卸载原生 detour 的成本随数量放大。动画、回收、激活和 HealthManager 钩子统一注册，按对象 ID 分派；生命周期切换只修改本机表项。
- 初始化释放对象可能同步生成新实体，改用实体列表快照遍历，并在释放前确定角色，让新生成物正确初始化。
- 清理退役实体的观察者、待生成项和超时更新；静态/动态身份均不复用旧生命周期。
- 特殊死亡和额外伤害采用独立事件去重，终结 Death 明确执行普通原生死亡，不受旧的特殊死亡标志阻挡。
