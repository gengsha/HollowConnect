# 0.1.12 救援灵魂与原版暗影破碎反馈

存活玩家用骨钉击破队友的救援暗影后，被救玩家仍原地恢复 1 格血、0 格蓝血；服务器确认的实际救人者获得 **33 点灵魂**，相当于原版一次聚集的消耗。灵魂通过 `HeroController.AddMPCharge` 发放，灵魂槽、额外容器、灵魂限制与神居灵魂束缚的容量仍由原版处理，满容量不会溢出。快速聚集改变时间、深度聚集改变恢复格数，均不改变此奖励量。

同房间玩家看见原版自己的暗影被击破时使用的 `Death Start`、`Death`、`Death Glow` 与暗影粒子，并听见同一原版流程的 `boss_explode_clean` 和 `hero_void_scream_spell`。音效使用原版混音通道。动画和粒子按真实时间推进，最多 2.5 秒后清理，暂停或受击停顿不会积累残影。

只复制原版 `Hollow Shade Death` 的表现素材。复制体在激活前移除原版 FSM、碰撞及其他游戏逻辑，避免其 `AddGeoQuietly`、`geoPool = 0`、`shadeScene = None`、`SOUL LIMITER DOWN` 和 `HOLLOW SHADE KILLED` 等个人回收行为运行。粒子上限受控；没有运行原版暗影的 AI、掉钱、回收或保存逻辑。

普通正式死亡留下的个人暗影仍属于原版个人存档，队友看不到。救援奖励不会清除旧暗影、回收旧吉欧或修复旧暗影造成的灵魂限制。放弃救援、全队失败、挥空、无效死亡编号和被服务器拒绝的命中不发奖励。

可靠的救援确认现在同时携带被救者与救人者的 ID。奖励和表现按死亡编号去重，并核对会话、重试编号和生命版本；即使不可靠的存活名单先到，救援确认仍能触发一次反馈。旧确认不能救起下一次倒地。

## 验证

原版依据：本机 Modding API 游戏程序集 SHA-256 `5944411BD93830369390A4B51766EE68C4AB26195B299E25A07B5E7D0E00086D`；原版 `PlayerData.focusMP_amount` 初值为 33；隔离运行检查了 `Hollow Shade Death / Shade Control` 的资源与状态。

最终二进制验证记录见 [运行证据](evidence/runtime-rescue-0.1.12.json)，自动化输出见 [回归记录](evidence/regression-0.1.12.txt)，安装器检查见 [安装器记录](evidence/installer-portable-0.1.12.txt)。本次测试覆盖救援实际骨钉命中、双方互救、奖励归属、容量/储备、保留个人暗影状态、名单先到/重复/旧事件、暂停清理，以及原版正式死亡与完整协作流程。本次没有重复逐个 Boss 的实战验收，也没有完成真实双机 FRP 测试。

房主和队友必须一起更新至 **0.1.12**；包内 HKMP 引擎仍为 `3.0.0-hc8`。安装器继续自动查找各盘 Steam 库，并支持手选自己的游戏目录。
